# 2단계 설계 — 디자인 시스템

`[가칭] 납입배분 계산기`의 시각·상호작용 규약이다. `screens.md`가 이 문서의 토큰과 컴포넌트만으로 화면을 기술한다. 코드는 없다 — 구현은 3단계 `web-dev`의 몫이다.

---

## 0. 이 시스템이 지켜야 하는 것

이 제품의 설득력은 심미성이 아니라 **"이 숫자가 어디서 나왔는지 화면이 스스로 밝힌다"**는 데서 나온다. 헌장의 세무사법 준수 원칙이 디자인 제약으로 번역되면 다음 넷이다.

| # | 원칙 | 디자인 규약 |
|---|---|---|
| P1 | 금액을 산정 조건 없이 앞세우지 않는다 | **금액 컴포넌트는 조건 캡션 슬롯 없이 단독으로 존재할 수 없다.** 큰 금액 뒤에는 항상 같은 카드 안에 조건 한 줄이 붙는다. 6.5절 |
| P2 | 계산에 쓴 법령 조항을 결과 화면에 노출한다 | `조항 칩(LawChip)`과 `근거 블록(BasisBlock)`을 1급 컴포넌트로 둔다. 툴팁·각주가 아니다. 5.9·5.10절 |
| P3 | 개인 지시형 문장을 쓰지 않는다 | 버튼·라벨·헤딩 문구에 2인칭 명령형을 쓰지 않는다. 7.2절의 금지 패턴 목록 |
| P4 | 고지를 각주로 밀지 않는다 | 고지 텍스트는 본문과 같은 색 대비(4.5:1 이상)를 쓰고, 본문보다 두 단계 이상 작게 만들지 않는다. 캡션 최소 크기는 12.5px로 고정한다. 2.1절 |

**"작게, 회색으로, 접어서"가 고지의 기본값이 되는 것을 이 시스템이 구조적으로 막는다.** 그래서 캡션 토큰의 색이 `text-muted`가 아니라 `text-secondary`이고, `BasisBlock`과 `AssumptionBlock`의 기본 상태가 "접힘"이 아니라 "펼침"이다.

## 1. 기반 단위

- **기준 폰트 크기** 16px = 1rem. 사용자의 브라우저 기본 크기를 존중한다 — 루트에 `px` 고정값을 박지 않는다.
- **기준 격자** 4px. 모든 간격·크기는 4의 배수다.
- **최대 본문 폭** 결과 설명 텍스트는 68자를 넘지 않는다(한글 기준 약 34~40자).
- **최소 터치 타깃** 44×44px. 조항 칩처럼 작은 요소도 히트 영역은 44px를 확보한다.

## 2. 타이포그래피

### 2.1 스케일

| 토큰 | 크기 / 행간 | 굵기 | 자간 | 쓰임 |
|---|---|---|---|---|
| `type-display` | 40px / 1.10 | 700 | -0.02em | 절감세액 헤드라인 금액. 화면당 **1회만** |
| `type-display-sub` | 28px / 1.20 | 700 | -0.015em | 대안 배분안의 절감세액, 모바일의 헤드라인 금액 |
| `type-title-l` | 24px / 1.30 | 700 | -0.01em | 패널 제목("계산 결과", "입력") |
| `type-title-m` | 20px / 1.35 | 600 | -0.01em | 섹션 제목("계좌별 배분", "적용한 법령 조항") |
| `type-title-s` | 17px / 1.40 | 600 | 0 | 카드 제목, 입력 그룹 제목 |
| `type-body` | 16px / 1.60 | 400 | 0 | 본문. 입력 필드 값도 이 크기 |
| `type-body-strong` | 16px / 1.60 | 600 | 0 | 본문 강조, 계좌명 |
| `type-body-s` | 14px / 1.55 | 400 | 0 | 필드 라벨, 보조 설명 |

| `type-caption-strong` | 12.5px / 1.50 | 600 | 0.005em | 고지 블록의 항목 제목, 배지 |

**`type-num`의 tabular-nums는 선택이 아니다.** 시나리오 세 개의 금액이 세로로 정렬될 때 숫자 폭이 흔들리면 자릿수 비교가 불가능해진다. 결과 화면의 스택바 3행 비교(`screens.md` 5.5절)가 이 정렬에 의존한다.

### 2.2 서체 스택

```
본문/숫자 공통:
  system-ui, -apple-system, "Segoe UI", "Apple SD Gothic Neo",
  "Noto Sans KR", "Malgun Gothic", sans-serif
```

별도 웹폰트를 전제하지 않는다(`open_questions`). 어떤 서체를 쓰든 **한글과 아라비아 숫자의 기준선이 어긋나지 않을 것**과 **tabular-nums를 지원할 것** 두 가지가 채택 조건이다.

### 2.3 텍스트 규칙

- 금액은 천 단위 쉼표 + `원` 접미. 만 단위 축약(`147만원`)은 **헤드라인에서만** 허용하고, 계좌별 상세와 근거 블록에서는 항상 원 단위 전체 표기를 병기한다. 축약만 남기면 사용자가 자기 계산과 대조할 수 없다.
- 마이너스 금액은 색이 아니라 부호와 라벨로 표시한다(색맹 대응).
- 줄바꿈: 금액과 단위(`원`)는 분리되지 않는다.
- 한국어 조사 자동 결합("을/를")을 문자열 조립으로 처리하지 않는다 — 문장을 조사가 필요 없는 형태로 쓴다.

## 3. 색 — 역할 정의

색은 **역할(role)로만** 참조한다. 화면 설계 문서와 구현 어디에도 raw hex가 직접 등장하지 않는다.

hex는 **참조값**이다. 역할이 성립하는지 검증하려고 채워 넣은 값이며, 브랜드 확정 시 교체 대상이다(`open_questions`). 특정 금융사의 브랜드 색은 참고하지 않았다.

| `surface-base` | 페이지 바탕 | `#F7F8FA` | `#14171A` |
| `surface-raised` | 카드·패널 | `#FFFFFF` | `#1E2226` |
| `surface-sunken` | 입력 필드 안쪽, 막대 트랙 | `#EDEFF2` | `#0F1214` |

### 3.5 데이터 색 — 계좌 고정 매핑

| 토큰 | 매핑 | 라이트 | 다크 |
|---|---|---|---|
| `data-pension` | 연금저축 | `#2E7D8A` | `#4FB3C4` |
| `data-irp` | IRP | `#B4762B` | `#E0A249` |
| `data-isa` | ISA | `#6B5BA6` | `#9B8BD6` |
| `data-unallocated` | 미배분 잔액 | `#9AA3AB` | `#6E7780` |
| `data-track` | 납입 잔여 한도 트랙(빈 부분) | `#E1E5EA` | `#2C3238` |

규약 넷.

1. **계좌↔색 매핑은 제품 전체에서 고정이다.** 시나리오가 바뀌어도, 차트가 바뀌어도, 공유 이미지에서도 같다.
2. **색만으로 구분하지 않는다.** 모든 색 조각에는 직접 라벨(계좌명 + 금액)이 붙는다. 범례만 두고 라벨을 빼는 설계는 금지다.
3. **개정예고 데이터는 색을 바꾸지 않고 패턴을 얹는다** — 45° 사선 해칭. 색을 바꾸면 계좌 매핑이 깨진다. 패턴은 색각이상·흑백 인쇄에서도 살아남는다.
4. 세 색은 적록색각이상(deuteranopia/protanopia)에서 명도·색상이 모두 갈리도록 골랐다. 교체 시 시뮬레이터로 재검증한다.

### 4.2 반경

`radius-s` 4px(칩·배지) · `radius-m` 8px(필드·버튼) · `radius-l` 12px(카드) · `radius-xl` 16px(모달·시트) · `radius-full` 999px(막대 끝, 토글)

### 4.3 그림자

`shadow-1` 카드: `0 1px 2px rgba(16,18,20,.06), 0 1px 3px rgba(16,18,20,.04)`
`shadow-2` 스티키 패널·드롭다운: `0 4px 12px rgba(16,18,20,.10)`
`shadow-3` 모달·시트: `0 12px 32px rgba(16,18,20,.18)`

다크 테마에서는 그림자를 절반으로 줄이고 `border-subtle`로 경계를 대신한다.

### 4.4 레이아웃 격자

| 뷰포트 | 격자 | 좌우 여백 | 비고 |
|---|---|---|---|
| `< 768px` (모바일) | 4열, 거터 16px | 16px | 단일 열 |
| `768~1023px` (태블릿) | 8열, 거터 20px | 24px | 단일 열 유지 + 스티키 요약 바 |
| `≥ 1024px` (데스크톱) | 12열, 거터 24px | 32px | 좌우 분할 |
| `≥ 1440px` | 12열, 최대 1360px 중앙 정렬 | 자동 | 분할 비율 유지 |

**좌우 분할 비율(데스크톱): 좌 5열 / 우 7열.** 입력 패널 최소 400px·최대 520px, 나머지를 결과 패널이 갖는다. 결과가 주인공이므로 넓은 쪽을 준다.

## 5. 컴포넌트

각 컴포넌트의 **기본 / 호버 / 포커스 / 비활성 / 오류** 상태를 정의한다. 해당 없는 상태는 "해당 없음"으로 명시했다 — 빈칸으로 두면 구현 단계에서 임의로 채워진다.

### 5.1 `TextField` / `NumberField` / `CurrencyField`

라벨(위, `type-body-s`, `text-secondary`) → 필드 → 도움말 또는 오류(아래, `type-caption`).

| 상태 | 명세 |
|---|---|
| 기본 | 높이 48px, `surface-sunken` 바탕, `border-strong` 1px, `radius-m`, 좌우 패딩 `space-3`. 값은 `type-body` + `text-primary` |
| 호버 | 테두리 `accent` 40% 혼합. 바탕 변화 없음 |
| 포커스 | 테두리 `accent` 1px + 바깥 `focus-ring` 2px(offset 2px). 바탕 `surface-raised`로 밝아진다 |
| 비활성 | 바탕 `surface-sunken`, 텍스트·테두리 `text-muted`, 커서 `not-allowed`. **조건부 노출 필드는 비활성이 아니라 미표시로 처리한다** (요구사항 AC: ISA 누적 납입액이 0이면 전환 항목을 "표시하지 않는다") |
| 읽기전용 | 테두리 없음, 바탕 투명, 값만 표시. 계산 결과를 되비출 때만 |
| 오류 | 테두리 `state-error` 1.5px, 바탕 `state-error-subtle`, 아래에 오류 메시지(`type-caption`, `state-error`) + 경고 아이콘. `aria-invalid`, `aria-describedby` 연결 |

`CurrencyField` 추가 규약: 우측에 고정 접미 `원`(`text-secondary`), 입력 중 천 단위 쉼표 자동 삽입, 값은 `tabular-nums`. **음수 입력 자체를 막지 않고 입력은 받되 오류로 표시한다** — 요구사항 AC가 "오류를 표시한다"이지 "입력을 막는다"가 아니다.

### 5.2 `SelectField` / `RadioGroup`

ISA 계좌 유형 2택, ISA 만기 전환 여부 2택에 쓴다. 선택지가 3개 이하이면 `RadioGroup`(가로 세그먼트)을 기본으로 한다 — 드롭다운을 열지 않고 선택지를 다 보여주는 편이 "선택지 비교"라는 이 제품의 성격에 맞는다. 선택지가 4개 이상이거나 각 선택지에 설명이 붙으면 세로 목록형(`HorizonChoiceGroup`, 5.22절)을 쓴다.

| 상태 | 명세 |
|---|---|
| 기본 | 세그먼트 한 칸: 높이 44px, `surface-sunken`, 텍스트 `text-secondary` |
| 선택됨 | 바탕 `accent-subtle`, 테두리 `accent` 1.5px, 텍스트 `text-primary` + 600 |
| 호버 | 바탕 `surface-raised` |
| 포커스 | 그룹 전체가 아니라 **선택 항목 하나**에 `focus-ring` 2px. 방향키로 이동 |
| 비활성 | 전체 그룹 흐림 + `aria-disabled`. 개별 선택지만 비활성인 경우 사유를 캡션으로 함께 표시한다 |
| 오류 | 그룹 테두리 `state-error`, 아래 오류 캡션 |

### 5.3 `ConditionalGroup`

ISA 만기 전환 항목처럼 상위 값에 따라 나타나는 필드 묶음.

- 나타남: 높이 애니메이션 180ms `ease-out`, 좌측에 `border-subtle` 2px 세로선 + 좌패딩 `space-4`로 종속 관계를 시각화.
- 사라짐: 즉시 제거하고 그 안의 값을 0으로 되돌린다. **값을 남겨두고 숨기면 사용자가 모르는 값이 계산에 들어간다.** 사라질 때 결과 패널에 "ISA 만기 전환 항목이 계산에서 제외되었습니다" 한 줄을 3초간 표시한다.
- `prefers-reduced-motion`이면 애니메이션 없이 전환한다.

### 5.4 `Button`

| 변형 | 기본 | 호버 | 포커스 | 비활성 | 오류 |
|---|---|---|---|---|---|
| `primary` | `accent` 바탕, `text-on-accent`, 높이 48px, `radius-m` | `accent-hover` | `focus-ring` 2px offset 2px | `surface-sunken` 바탕 + `text-muted`. **비활성 사유를 버튼 아래 캡션으로 반드시 표시** | 해당 없음 |
| `secondary` | 투명 바탕, `border-strong`, `text-primary` | 바탕 `surface-sunken` | 동일 | 테두리·텍스트 `text-muted` | 해당 없음 |
| `text` | 텍스트만, `text-link` | 밑줄 | 동일 | `text-muted` | 해당 없음 |
| `danger` | 투명 바탕, `state-error` 테두리·텍스트 | 바탕 `state-error-subtle` | 동일 | `text-muted` | 해당 없음 |

**비활성 버튼은 사유 없이 존재할 수 없다.** "계산하기"가 비활성이면 그 아래에 남은 항목 수가 붙는다. 이 규약이 `screens.md`의 입력 부족 상태 설계와 짝을 이룬다.

### 5.5 `RequirementChecklist`

입력 부족 상태의 주인공. 결과 패널이 "무엇을 더 넣으면 결과가 나오는가"를 답하는 컴포넌트다.

- 항목: `[○] 나이` / `[●] 총급여액` 형태. 채워짐은 채운 원 + `text-secondary` + 취소선 없음(취소선은 실패의 인상을 준다), 미충족은 빈 원 + `text-primary`.
- **각 항목은 버튼이다.** 누르면 해당 입력 필드로 스크롤 + 포커스. 모바일에서는 입력 영역으로 스크롤한다.
- 상단에 진행 표시: `n / m 항목` + 가로 진행 막대(`accent`, 높이 4px, `radius-full`).
- **분모 `m`은 무조건 필수인 항목 수로 고정한다.** 조건부로 생기는 필수 항목(예: ISA 만기 전환을 선택했을 때의 전환 금액)은 분모에 넣지 않는다 — 넣으면 사용자가 값을 채우는 도중에 진행 막대가 뒤로 가는 것처럼 보인다. 대신 목록 아래에 **별도 줄**로 붙이고, 무조건 필수가 다 찼는데 조건부가 남았으면 `m / m · 추가 항목 k개`로 표시한다. 다 채웠는데 결과가 없는 상태를 설명 없이 두지 않는다.
- 상태: 기본 / 호버(바탕 `surface-sunken`) / 포커스(`focus-ring`) / 비활성(해당 없음 — 항목이 비활성이면 표시하지 않는다) / 오류(해당 항목이 오류 상태이면 원 대신 `state-error` 경고 아이콘 + 오류 요약).

### 5.6 `AmountCard` — 금액 표시의 유일한 통로

**P1의 구조적 장치.** 금액을 크게 보이려면 반드시 이 컴포넌트를 쓴다. 슬롯이 셋이고 셋 다 필수다.

```
┌────────────────────────────────────────────┐
│ 라벨          (type-body-s / text-secondary)│  ← 슬롯1 (필수)
│ {금액}        (type-display / text-primary) │  ← 슬롯2 (필수)
│ 조건 캡션     (type-caption / text-secondary)│  ← 슬롯3 (필수, 비울 수 없음)
└────────────────────────────────────────────┘
```

- 슬롯3에는 기준 과세연도 · 적용 대상(소득 구간 등) · 주요 가정이 한 줄로 들어간다. 예: `2026 과세연도 기준 · 입력한 총급여 구간 적용 · 다른 소득공제 미반영`
- 슬롯3이 비면 컴포넌트가 성립하지 않는다. 구현에서 빈 문자열을 허용하지 않는다.
- 개정예고 룰이 쓰였으면 라벨 우측에 `ProposedBadge`가 붙는다.
- 상태: 기본 / 로딩(슬롯2가 `Skeleton`, 슬롯1·3은 실제 텍스트 유지) / 오류(슬롯2에 `—` + 슬롯3에 사유) / 비활성·호버·포커스 해당 없음(비대화형).

### 5.7 `AllocationBar` — 한도 트랙 막대

계좌 하나의 배분을 나타내는 가로 막대. 결과 화면 확정안에서 입체 도넛 바로 아래에 놓이며, **도넛의 원근 왜곡을 검산할 수 있는 왜곡 없는 표현**을 겸한다(`screens.md` 5.4절).

```
연금저축                       {월 배분액} / 월        ← 라벨 행
█████████████░░░░░░░░░░░░░░░░░░░░░  ← 채움 + 트랙
└ 납입 잔여 한도 대비 {n}% · 기납입 {금액} 반영
```

- **트랙 전체 길이 = 해당 계좌의 `contribution_limit_remaining_krw`(납입 잔여 한도).** 채움 = 이번 배분액. 트랙 왼쪽 끝에 사선 해칭으로 **기납입액** 구간을 표시할 수 있다(선택).
- **`credit_eligible_limit_remaining_krw`를 트랙 기준으로 쓰지 않는다.** 그 값은 배분 상한이 아니어서 채움이 트랙을 넘는 그림이 나올 수 있다(`screens.md` 5.10절). 트랙-채움 관계는 **넘을 수 없는 상한**에만 성립한다.
- 높이 20px, `radius-full`, 트랙 `data-track`, 채움은 계좌 색.
- 계좌 세 개의 트랙 길이는 **서로 다른 스케일을 쓰지 않는다.** 같은 픽셀=같은 금액이어야 계좌 간 비교가 성립한다. 한 계좌의 한도가 화면을 넘치면 전체를 축소하지 말고 **공통 배율**을 낮춘다.
- 상태:
  - 기본 / 호버(트랙 위 툴팁으로 정확한 금액 — 단, 툴팁이 유일한 정보 전달 수단이 되면 안 된다. 금액은 라벨 행에 이미 있다) / 포커스(막대가 tabbable, `focus-ring`, 스크린리더는 `연금저축, 월 {금액}, 납입 잔여 한도의 {n}%`)
  - **배분액 0**(자격은 있으나 이 배분안에서 배분되지 않음): 채움 없이 트랙만 + `이 배분에서는 배분하지 않음` 캡션
  - **배분 대상 아님**(`eligible: false`): 트랙을 `data-track` 실선으로 채우지 않고 **`border-subtle` 1px 점선 윤곽만** 그린다. 금액 자리에 `배분 대상 아님`. 사유 문장과 `LawChip`이 캡션에 붙는다. **행 자체는 지우지 않는다** — 계좌 순서가 항상 같아야 하고, 계좌가 사라지면 사용자가 그 계좌를 왜 못 보는지 알 수 없다
  - 오류(해당 계좌 계산 실패): 트랙을 `state-error` 점선으로
- **빈 실선 트랙과 점선 윤곽은 다른 뜻이다.** 전자는 "한도는 있는데 이번에 안 채웠다", 후자는 "이 계좌는 이번 계산의 대상이 아니다". 같은 모양으로 그리면 두 상태가 구분되지 않는다.

### 5.8 배분안 이름 규약

**별도의 선택기 컴포넌트를 두지 않는다.** 배분안 전환은 `ScenarioStackBar`(5.21절)의 행 클릭이 겸한다 — 비교 그림과 선택기를 분리하면 같은 것을 두 번 말하게 된다(`screens.md` 4.1절). 여기서는 어디에 쓰이든 지켜야 할 **이름 규약**만 정한다.

- 이름은 **계산이 무엇을 우선했는지**를 그대로 부른다: `세액공제액이 가장 큰 배분` · `연금저축을 먼저 채우는 배분` · `ISA를 먼저 채우는 배분`. 엔진 계약의 배분안 종류와 1:1로 대응한다.
- 기본안에는 `기본` 표시만 단다.
- **"추천"·"최적"·"권장"을 이름에 쓰지 않는다.** 개인 지시로 읽힐 여지를 줄인다. 기본안이 최대 절세액이 아닐 수 있으므로(자금 사용 시점이 순서를 바꿀 수 있다) "최적"은 사실과도 어긋난다.
- 이름 옆에 절감세액(`type-caption`, tabular-nums)과 기본안 대비 차액을 함께 적는다.

### 5.9 `LawChip` — 법령 조항 칩

**P2의 최소 단위.** 룰셋의 `source.law` 문자열을 가공 없이 그대로 담는다.

```
[ 소득세법 §59조의3 ① ]
```

- `radius-s`, 테두리 `border-subtle`, 바탕 `surface-sunken`, `type-caption-strong`, `text-secondary`.
- 누르면 같은 화면의 `BasisBlock` 해당 항목으로 스크롤 + 하이라이트 1.2초. **새 페이지로 이동하지 않는다** — 헌장의 "같은 화면에서" 요구.
- 개정예고 룰이면 칩 좌측에 사선 해칭 4px 바 + `ProposedBadge` 인접.
- 상태: 기본 / 호버(바탕 `accent-subtle`) / 포커스(`focus-ring`) / 비활성(해당 없음) / 오류(룰셋에 `source.law`가 없으면 칩을 그리지 않고 그 자리에 `state-error` 캡션 `근거 조항 미표기 — 이 항목은 표시하지 않습니다`를 띄운다. 조항 없는 숫자를 화면에 내보내지 않는다).

### 5.10 `BasisBlock` — 근거 블록 (고지 ③)

적용된 모든 조항을 나열한다. **기본 상태가 펼침이다.**

- 각 행: `LawChip` + 규칙이 정한 내용 요약(한 문장) + 기준 과세연도 + `원문` 링크(`text-link`, 새 탭, `rel="noopener"`).
- 접기 가능하되, 접힌 상태에서도 헤더에 `적용 조항 {n}건 · 2026 과세연도 기준`이 남는다.
- 상태: 기본(펼침) / 접힘 / 로딩(행 스켈레톤 3줄) / 오류(`근거를 불러오지 못했습니다` + 결과 표시 자체를 중단) / 비활성·호버·포커스는 아코디언 헤더에만 적용.

### 5.11 `AssumptionBlock` — 가정 블록 (고지 ④)

서비스가 세운 가정을 항목으로 나열한다. 기본 펼침. 각 항목은 `type-body-s`, `text-secondary`.
`BasisBlock`과 시각적으로 같은 골격을 쓰되 아이콘·헤더 문구로 구분한다.

### 5.12 `DisclosureBanner` — 성격·자격 배너 (고지 ①②)

결과 패널 최상단. **접히지 않고, 스크롤로 밀려나도 결과 영역을 벗어날 수 없다.**

- 좌측에 정보 아이콘, 우측에 2문장. `type-caption`, `text-secondary`, 바탕 `state-info-subtle`, 좌측 3px `state-info` 바, `radius-m`.
- 상태: 기본 하나뿐. 닫기 버튼 없음. 접기 없음.

### 5.13 `LimitNote` — 한계 안내 (고지 ⑤)

결과 영역 하단 고정. `AssumptionBlock`과 같은 형태이나 접히지 않는다.

### 5.14 `ProposedBadge` — 개정예고 배지 (고지 ⑥)

```
[ 정부안 · 국회 통과 전 ]
```

- `radius-s`, 바탕 `state-info-subtle`, 텍스트 `state-info`, `type-caption-strong`, 좌측에 사선 해칭 4px 바.
- 룰셋의 `bill_stage` 값을 그대로 읽어 표시한다. 문자열을 재작성하지 않는다.
- 이 배지가 붙은 시나리오는 차트 계열에도 해칭이 적용되고, 시나리오 카드 상단에 한 줄 캡션(`이 시나리오는 아직 국회를 통과하지 않은 개정안을 반영한 계산입니다`)이 함께 붙는다. 배지 하나로 끝내지 않는다.

### 5.15 `Skeleton`

`surface-sunken` 바탕 + 1.2s 좌→우 밝기 이동. `prefers-reduced-motion`이면 정적. **스켈레톤 안에 숫자 모양을 그리지 않는다** — 실제 값으로 오인될 여지를 없앤다. 도형은 무채색 사각형뿐이다.

### 5.16 `InlineAlert`

| 변형 | 바탕 / 테두리 / 아이콘 | 쓰임 |
|---|---|---|
| `error` | `state-error-subtle` / `state-error` | 계산 불가, 필드 오류 요약 |
| `warning` | `state-warning-subtle` / `state-warning` | 미배분 잔액 발생, 한도 초과 입력 |
| `info` | `state-info-subtle` / `state-info` | 조건부 항목 제거 안내, 개정예고 |

제목(`type-body-strong`) + 본문(`type-body-s`) + 선택적 조치 버튼(`text` 변형). 상태: 기본 / 호버·포커스는 내부 버튼에만 / 비활성 해당 없음.

### 5.17 `Tooltip` / `HelpPopover`

입력 항목의 "이 값을 어디서 확인하나요" 안내에 쓴다.

- **툴팁은 보조 정보만 담는다.** 툴팁에만 존재하는 정보는 금지 — 터치 기기와 스크린리더에서 사라진다. 고지 여섯 요소 중 어느 것도 툴팁에 담지 않는다.
- 트리거는 44px 히트 영역의 아이콘 버튼. 클릭/탭으로 열고 `Esc`로 닫는다. 호버 전용 금지.

### 5.18 `Modal` / `BottomSheet`

저장·공유에 쓴다. 데스크톱은 중앙 모달(최대 폭 480px), 모바일은 바텀시트. 포커스 트랩, `Esc` 닫기, 열릴 때 배경 스크롤 잠금, 닫히면 트리거로 포커스 복귀.

### 5.19 `StickySummaryBar` (모바일 전용)

화면 하단 고정 56px 바. 입력 부족 상태면 `남은 항목 {n}개`, 결과가 있으면 `절감세액 {금액} · 결과 보기`. 탭하면 결과 시트가 올라온다.
상태: 입력 부족 / 계산 중(스켈레톤 + `계산 중`) / 결과 있음 / 오류(`state-error-subtle` 바탕 + `계산할 수 없습니다`).

### 5.20 `AccountDonut` — 입체 도넛

배분 비중을 원형으로 보여주는 주 시각화. **기하 파라미터가 고정값이고 반응형·애니메이션에서도 변하지 않는다.**

| 파라미터 | 값 | 변경 가능 여부 |
|---|---|---|
| 기울기 | 15° | **고정.** 크면 원근 왜곡이 커진다 |
| 압출 두께 | 반지름의 8% | **고정** |
| 시작각 | 12시 | **고정** |
| 조각 순서 | 연금저축 → IRP → ISA → 미배분, 시계방향 | **고정.** 값 크기순 정렬 금지 |
| 외경 | 뷰포트별 200 / 240 / 260px | 반응형으로 변함 |

- 조각 색은 계좌 고정 매핑(3.5절). 압출 측면은 상단면 색의 명도 −18%이며 별도 토큰을 만들지 않는다.
- 개정예고 해칭은 **상단면에만** 얹는다. 측면에 얹으면 원근 때문에 패턴 간격이 왜곡된다.
- 값 변화 시 조각 각도만 240ms로 바뀐다. **뷰 각도 회전·확대 애니메이션 금지.**
- 상태: 기본 / 호버(조각 밝기 +6%, 툴팁은 보조 정보만) / 포커스(조각이 tabbable, `focus-ring`, 스크린리더 `연금저축, 월 {금액}, 전체의 {n}%`) / 비활성(배분액 0이거나 배분 대상이 아닌 계좌는 조각을 그리지 않는다 — 그 계좌의 사정은 `AllocationBar` 행과 계좌별 표가 말한다) / 오류(도넛을 그리지 않고 그 자리에 `InlineAlert`).

**조각이 하나뿐일 때 — 반드시 지킬 렌더링 규약.**

한 계좌가 100%를 차지하면 조각의 시작각과 끝각이 같아지고, **호(arc) 하나로 그리면 아무것도 그려지지 않는다.** 배분 대상 계좌가 배제로 줄어들면 흔해지는 경로다.

- 360° 조각은 호가 아니라 **닫힌 고리**로 그린다. 두 개의 180° 호를 잇거나 원 두 개(외경·내경)의 차집합으로 만든다. 구현 방식은 자유이나 **결과가 폭 0이 되어서는 안 된다.**
- 이 규약은 조각이 2개일 때도 각도가 0에 가까운 조각에 적용된다 — 배분액이 0보다 크면 **최소 2° 이상**의 각을 보장하고, 그로 인한 각도 왜곡은 조각 라벨의 금액이 바로잡는다. 보이지 않는 조각보다 약간 부정확한 조각이 낫다.

### 5.21 `ScenarioStackBar` — 배분안 비교 스택바

같은 폭(= 월 납입 여력 100%)의 가로 막대를 배분안 수만큼 세로로 쌓는다. 조각 경계가 위아래로 정렬되는 것이 이 컴포넌트의 존재 이유다. 행 클릭이 배분안 전환을 겸한다(5.8절).

- 행 높이 28px, 행 간격 `space-2`. 조각 색은 계좌 고정 매핑 + `data-unallocated`.
- 우측에 절감세액과 기본안 대비 차액(`tabular-nums`).
- 상태: 기본 / 선택됨(좌측 `▸` + 행 바탕 `accent-subtle`) / 호버(행 바탕 `surface-sunken`) / 포커스(행이 tabbable, 방향키로 행 이동) / 비활성(성립하지 않는 배분안은 행 자체를 그리지 않는다) / 오류(해당 없음 — 계산 실패 시 결과 영역 전체가 오류 상태로 간다).
- **행마다 라벨 유무가 달라지지 않는다.** 조각 안에 라벨이 들어갈 폭이 안 되면 전 행이 범례로 통일한다.
- 행 우측에 그 배분안의 중도 불이익 안내 개수 표식(`▍n`)을 단다. 0이면 표식을 그리지 않는다.

### 5.22 `HorizonChoiceGroup` — 설명이 붙는 세로 선택지

`fund_use_horizon`(자금 사용 시점) 4택에 쓴다. 각 선택지가 라벨 + 설명 + **선택적 보조 캡션** 세 줄을 갖는 형태다.

```
┌──────────────────────────────────────┐
│ ○  라벨            (type-body-strong) │  ← 항상 있다
│    설명            (type-body-s)      │  ← 항상 있다
│    └ 보조 캡션      (type-caption)    │  ← 데이터가 오면 나타난다
└──────────────────────────────────────┘
```

- 각 항목 최소 높이 64px(터치 타깃 여유), 좌측 라디오 20px, `radius-m`, 항목 사이 `border-subtle` 1px.
- **보조 캡션 줄의 자리를 미리 예약한다.** 값이 늦게 도착해도 레이아웃이 밀리지 않아야 한다. 값이 끝내 오지 않으면 예약된 자리를 접는다.
- **보조 캡션은 라벨을 대신하지 못한다.** 캡션이 없어도 라벨 + 설명만으로 선택이 가능해야 한다 — 캡션에는 룰셋에서 온 수치가 들어가는데 그 수치가 없다고 입력이 막히면 안 된다(`screens.md` 3.4절).
- **미리 선택된 항목이 없다.** 이 컴포넌트를 쓰는 입력은 기본값을 갖지 않는다. "모르겠다"에 해당하는 선택지가 있더라도 그것 역시 사용자가 눌러야 선택된다.
- 그룹 아래에 **효과 고지 캡션**을 둔다 — 이 선택이 무엇을 바꾸고 무엇을 바꾸지 않는지. 필수 슬롯이며 비울 수 없다.
- 상태: 기본 / 선택됨(테두리 `accent` 1.5px + 바탕 `accent-subtle`) / 호버(바탕 `surface-sunken`) / 포커스(항목 하나에 `focus-ring`, 방향키 이동) / 비활성(항목 단위 비활성 시 사유 캡션 필수) / 오류(그룹 테두리 `state-error` + 아래 오류 캡션).

### 5.23 `WarningNote` — 중도 불이익 안내

계산 결과에 딸려 오는 규칙 안내를 담는다. **`InlineAlert`(5.16절)와 다르다** — `InlineAlert`는 사용자가 무언가를 고쳐야 하는 상태를 알리고, `WarningNote`는 고칠 것이 없는 사실을 알린다. 둘을 같은 컴포넌트로 만들면 결과가 오류처럼 보인다.

```
▍{문두(info일 때만)}{사실 서술 문장}
▍[법령 조항 칩]  [법령 조항 칩]
```

| 요소 | 명세 |
|---|---|
| 좌측 바 | 3px. `severity: warning`이면 `state-warning`, `info`면 `state-info` |
| 바탕 | 각각 `state-warning-subtle` / `state-info-subtle` |
| 아이콘 | 16px. 크게 키우지 않는다 |
| 본문 | `type-body-s`, `text-secondary`. **한 문장.** 여러 규칙이면 노트를 나눈다 |
| 조항 칩 | `LawChip` 1개 이상 **필수.** 칩 없는 `WarningNote`는 성립하지 않는다 |
| 금액 | **넣을 수 없다.** 금액 슬롯이 없는 컴포넌트다 |

- **제목 슬롯이 없다.** 제목을 두면 "주의"·"경고" 같은 말이 들어가고, 그것이 겁주는 화면의 시작이다.
- 문구 제약은 `screens.md` 4.7절의 표를 따른다. 느낌표·2인칭 지시·"손해"·"위험"을 쓰지 않는다.
- 상태: 기본(`warning`) / 기본(`info`) / 로딩(그리지 않는다 — 결과와 함께 온다) / 비활성·호버·포커스는 내부 `LawChip`에만 / 오류(해당 없음).

### 5.24 `EligibilityNote` — 배분 대상 아님 통지

계좌가 법령 요건 때문에 배분 대상에서 빠졌다는 **사실 통지**. `AccountEligibility.eligible: false`에 붙는다.

**`WarningNote`와 색이 다르다 — `state-info`를 쓰고 `state-warning`을 쓰지 않는다.** 근거: 배제는 사용자가 무언가를 잘못해서 생긴 상태가 아니고, 대비해야 할 위험도 아니다. 법령 요건에 해당하지 않는다는 사실일 뿐이다. 주의 색을 칠하면 사용자가 자기 상황을 결함으로 읽는다. 엔진이 이 notice를 `severity: warning`으로 내지만(`isa_excluded_*`), 그것은 **결과의 정확도에 영향을 준다는 뜻**이지 사용자에게 경고하라는 뜻이 아니다 — 화면의 색은 화면이 정한다.

| 요소 | 명세 |
|---|---|
| 좌측 바 | 3px `state-info` |
| 바탕 | `state-info-subtle` |
| 본문 | `type-body-s`. **한 문장으로 사유를 서술한다.** 주어는 법령 요건이지 사용자가 아니다 |
| 조항 칩 | `LawChip` 1개 이상 **필수** |
| 금액 | 넣지 않는다 |

- 문구는 `screens.md` 5.9절의 표를 따른다. `제외되었습니다`처럼 처분받은 인상을 주는 수동태보다 `이번 계산의 배분 대상이 아닙니다`처럼 상태를 서술한다.
- **조치를 지시하지 않는다.** `금융소득종합과세 대상이 아니라면 입력을 고쳐 주세요` 같은 문장을 붙이지 않는다 — 입력 패널에 이미 그 항목이 있다.
- 상태: 기본 하나뿐. 접기·닫기 없음.

## 6. 상호작용 규약

### 6.1 결과 갱신 시점 (확정 사항)

1. **필수 항목이 모두 유효해지기 전에는 계산하지 않는다.** 그전까지 결과 패널은 입력 부족 상태다.
2. 모두 유효해진 뒤부터는 값 변경 시 자동 재계산하되 **디바운스 400ms**를 둔다. 타이핑 도중 매 글자 갱신하지 않는다.
3. 금액 필드는 **디바운스 + blur 우선**: 필드에서 포커스가 빠지면 디바운스를 기다리지 않고 즉시 계산한다.
4. 재계산 중에도 **직전 결과를 화면에 남긴다.** 화면을 비우고 스켈레톤으로 되돌리면 값이 깜빡여 읽을 수 없다. 대신 결과 영역 우상단에 `갱신 중` 인디케이터를 띄우고 영역 투명도를 92%로 낮춘다.
5. 새 결과가 들어오면 변경된 금액에 220ms 배경 하이라이트. 숫자 롤링 애니메이션은 쓰지 않는다 — 중간값이 실제 값으로 오인된다.

### 6.2 모션

| 용도 | 시간 / 이징 |
|---|---|
| 상태 전환(색·투명도) | 120ms `ease-out` |
| 펼침/접힘 | 180ms `ease-out` |
| 막대·차트 값 변화 | 240ms `ease-out`. **길이만 변한다. 회전·확대 없음** |
| 모달/시트 | 200ms `ease-out` |

`prefers-reduced-motion: reduce`이면 전부 0ms로 처리하고 즉시 전환한다.

### 6.3 포커스

- 포커스 링은 어떤 경우에도 제거하지 않는다. 2px `focus-ring` + 2px offset.
- 탭 순서: 헤더 → 입력 패널(위→아래) → 결과 패널(위→아래) → 푸터. 결과가 시각적으로 오른쪽에 있어도 DOM 순서가 곧 읽기 순서다.
- 결과가 처음 생성되는 순간 포커스를 옮기지 않는다. 대신 `aria-live="polite"`로 `계산 결과가 표시되었습니다`를 알린다.

### 6.4 접근성 기준선

- 텍스트 대비 4.5:1(큰 텍스트 3:1). **고지 문구도 예외 없이 4.5:1.**
- 데이터 색 대비: 인접 조각 간 3:1 이상 + 각 조각에 직접 라벨.
- 색맹 시뮬레이션(deuteranopia, protanopia, tritanopia) 통과. 흑백 인쇄에서도 조각이 구분될 것(패턴 또는 명도차).
- 모든 차트에 텍스트 대체 경로: 차트 바로 아래 `계좌별 상세 리스트`가 같은 정보를 표 형태로 담는다. **차트는 리스트의 시각화이지 유일한 정보원이 아니다.**
- 200% 확대에서 가로 스크롤 없이 동작.

### 6.5 금액 표시 규약 (P1의 실행)

- 화면에서 가장 큰 금액은 하나뿐이다(`type-display`). 그 금액은 반드시 `AmountCard` 안에 있다.
- 금액 옆·아래 24px 이내에 산정 조건 캡션이 있어야 한다. 다른 카드로 밀거나, 스크롤해야 보이거나, 접혀 있으면 위반이다.
- 헤드라인 금액에 `약`·`예상` 같은 완화어를 붙이되, 완화어가 조건 캡션을 대신하지 못한다. 둘 다 필요하다.

## 7. 문구 규약

### 7.1 어휘

헌장의 목록을 그대로 따른다. 화면에 등장할 수 있는 어휘로 한정하면 다음과 같다.

- **쓴다:** 계산 · 계산 결과 · 모의 계산 · 시뮬레이션 · 비교 · 납입 배분 · 배분 계산 · 세액공제액 · 예상 세액공제액 · 한도 · **납입 잔여 한도** · 비과세 한도 · 참고 정보 · 법령 조항 인용
- **"잔여 한도"를 수식어 없이 쓰지 않는다.** 이 제품에는 성격이 다른 한도가 둘 있다 — 넘을 수 없는 **납입 잔여 한도**와, 넘을 수 있는 **세액공제 인정 여지**다. 수식어 없는 "잔여 한도"는 둘을 뭉개고, 후자에 붙으면 사실과 어긋난다(`screens.md` 5.10절).
- **조건부로 쓴다:** `절세액`(계산 결과를 가리킬 때만) · `환급세액` · `납입 배분 최적화`(대상 명시) · `추천`(선택지 비교 맥락에서만)
- **쓰지 않는다:** 세무/세금 상담 · 자문 · 대리 · 컨설팅 · 진단 · 점검 · 신고 대행 · 환급 신청 · 전문가 검토 · 세무사 관련 일체

**서비스 명칭:** 확정 전까지 `[가칭] 납입배분 계산기`. "세무·택스·절세·컨설팅·환급·상담·자문·대행" 계열을 쓰지 않는다.

### 7.2 금지 문장 패턴 (P3)

| 금지 | 대체 |
|---|---|
| "당신은 IRP에 ○○원을 넣으세요" | "IRP 납입 잔여 한도까지 채우는 배분: 월 ○○원" |
| "이 배분을 추천합니다" | "세액공제액이 가장 큰 배분(계산 결과)" |
| "○○하는 것이 유리합니다" | "○○일 때 세액공제액이 {금액} 더 큽니다" |
| "지금 가입하세요" | (버튼·CTA 자체를 두지 않는다. 이 제품은 가입을 연결하지 않는다) |
| "평균 ○○만원 절세" | (금지. 산정 조건 없는 금액 표시) |

**동사의 주어를 사용자에게 두지 않는다.** 결과 문장의 주어는 항상 계산 대상(배분·한도·세액공제액)이다.

### 7.3 오류 메시지

- 무엇이 잘못됐는지 + 무엇을 하면 되는지, 두 조각으로만 쓴다.
- 사용자를 탓하지 않는다("잘못 입력했습니다" ✗ / "0 이상의 값이 필요합니다" ○).
- 계산 불가 사유는 법령 조건에서 나온 것이면 해당 `LawChip`을 함께 붙인다. 서비스가 임의로 막는 것이 아님을 보인다.

## 8. 다크 테마

- 색 토큰 교체만으로 성립하게 설계했다. 레이아웃·간격·타이포는 동일하다.
- 다크에서는 그림자 대신 `border-subtle`이 경계를 담당한다.
- 데이터 색은 다크 전용 값을 별도로 갖는다(3.5절). 라이트 값을 그대로 쓰면 어두운 바탕에서 채도가 죽는다.
- 순수 검정(`#000`)과 순수 흰색 텍스트를 쓰지 않는다 — 명도 대비가 과해 잔상이 생긴다.

## 9. 자산 제약

- **특정 금융사의 로고·브랜드 색·상품 이미지를 쓰지 않는다.** 계좌 아이콘이 필요하면 추상 도형(원·사각·삼각)으로 처리한다.
- 세무사·회계사를 연상시키는 시각 요소를 쓰지 않는다 — 가운·도장·법전·저울·배지·"전문가" 아이콘 일체 금지(`tax-rules-report.md` 2.4절이 오인 위험 요소로 명시한 유형).
- 인물 사진·일러스트를 쓰지 않는다. 사람이 개입한다는 인상을 만들지 않는다.
- 아이콘은 단색 선형 24px 격자 기준. 아이콘 단독으로 의미를 전달하지 않고 항상 텍스트 라벨과 짝을 이룬다.
