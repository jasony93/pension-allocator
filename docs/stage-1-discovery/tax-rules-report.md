# 세법 룰셋 조사 리포트 (1단계 발견)

- 조사일: 2026-08-08
- 조사 유닛: `tax-domain`
- 산출 룰셋: `data/tax-rules/2026.json`(확정 19건), `data/tax-rules/2027-proposed.json`(개정예고 6건)

## 1. 요약

ISA·연금저축·IRP의 과세 규칙 중 **납입 단계 최적화에 필요한 것**을 우선해 조사했다.

핵심 구조는 세 축이다.

1. **연금계좌(연금저축 + IRP)의 세액공제** — 소득에 따라 12% 또는 15%(지방소득세 포함 13.2% / 16.5%), 연금저축 단독 600만원 · 합산 900만원 한도. 이 제품이 답해야 할 "얼마를 어디에" 질문의 뼈대다.
2. **ISA의 비과세와 저율 분리과세** — 순소득 기준 200만원(서민형 400만원) 비과세, 초과분 9%(지방세 포함 9.9%) 분리과세, 계좌 내 손익통산. 세액공제는 없지만 **운용수익에 붙는 세금**을 줄인다.
3. **두 축을 잇는 다리** — ISA 만기 자금을 연금계좌로 옮기면 전환금액의 10%(최대 300만원)만큼 세액공제 한도가 추가로 열린다. ISA와 연금계좌를 따로 계산하면 이 조합 이득을 놓친다.

경계값은 네 개가 결정적이다. **종합소득금액 4,500만원 / 총급여 5,500만원**(공제율 12%↔15%), **직전 총급여 5,000만원 / 직전 종합소득금액 3,800만원**(ISA 일반형↔서민형), **연 1,500만원**(사적연금 분리과세), **55세 · 가입 후 5년**(연금수령 자격).

개정 쪽은 발표 닷새 전인 **2026-08-03에 나온 「2026년 세제개편안」**이 전부다. 핵심은 **생산적금융 ISA 신설**(이자·배당 전액 비과세, 연 2,000만원·총 2억원, 2027-01-01 시행 예정)이다. 확정된 것이 아니라 정부안이며, 국회를 통과하지 못하는 사례가 실제로 있었다(아래 5절).

## 2. 명시적 가정 — requirements.md 부재

`docs/stage-1-discovery/requirements.md`는 같은 1단계 동료 `product-planner`의 산출물이라 조사 시작 시점에 없었다. 헌장 5.4절에 따라 다음을 가정으로 세우고 진행했다. **게이트 1에서 실제 요구사항과 대조가 필요하다.**

| # | 가정 | 근거 |
|---|---|---|
| A1 | 사용자 입력은 **나이, 연간 총급여(또는 종합소득금액), 연간 납입 여력, 기존 계좌 보유 현황** 수준이다 | 설계 스펙 1절 "나이, 소득 수준, 월 납입 여력, 투자 성향" |
| A2 | 다루는 계좌는 **ISA, 연금저축, IRP** 세 가지다 | 스펙 1절과 유닛 정의의 명시 범위 |
| A3 | 최적화 대상은 **납입 단계의 절세액**이다. 인출 단계는 참고 정보로만 다룬다 | 스펙 1절 "얼마를 어떤 비중으로 납입해야" |
| A4 | **국민연금·퇴직소득세·금융투자소득세·주택청약저축은 범위 밖**이다 | 스펙이 세 계좌만 지목 |
| A5 | 단일 과세연도(2026) 기준으로 계산하며 다년도 시뮬레이션은 하지 않는다 | 룰셋 파일이 연도별로 나뉘는 구조 |

A3이 뒤집혀 인출 단계까지 계산한다면 **연금수령한도 산식**과 **이연퇴직소득 감면율**을 추가로 확정해야 한다. 둘 다 이번에 확인하지 못했다(머리말 `open_questions`).

## 3. 확정 룰셋 (`2026.json`) — 19건

### 3.1 연금계좌 (11건)

| id | 내용 | 근거 |
|---|---|---|
| `pension.credit.rate` | 세액공제율 15%(종합소득금액 4,500만원 이하 / 근로소득만이면 총급여 5,500만원 이하) 또는 12% | 소득세법 §59조의3 ① |
| `pension.credit.limit.annuity_savings` | 연금저축계좌 공제대상 납입한도 600만원 | 소득세법 §59조의3 ① 단서 |
| `pension.credit.limit.combined` | 연금저축(600만원 이내) + 퇴직연금 합산 900만원 | 소득세법 §59조의3 ① 단서 |
| `pension.credit.isa_transfer.extra_limit` | ISA 전환금액 × 10%, 최대 300만원 추가한도 | 소득세법 §59조의3 ③④ |
| `pension.contribution.annual_limit` | 연금계좌 연간 납입한도 1,800만원(계좌 합산) | 소득세법 시행령 §40조의2 ②1가 |
| `pension.withdrawal.eligibility` | 55세 이후 개시 신청 + 가입일부터 5년 경과 + 연금수령한도 이내 | 소득세법 시행령 §40조의2 ③ |
| `pension.income.withholding_rate.by_age` | 70세 미만 5% / 70~80세 미만 4% / 80세 이상 3% | 소득세법 §129 ①5의2 가 |
| `pension.income.withholding_rate.lifetime_annuity` | 종신계약 3% | 소득세법 §129 ①5의2 다 |
| `pension.income.separate_taxation.threshold` | 사적연금 연 1,500만원 이하 분리과세 | 소득세법 §14 ③9 |
| `pension.income.separate_taxation.elective_rate` | 초과 시 종합과세 vs 15% 분리과세 선택 | 소득세법 §64조의4 |
| `pension.early_withdrawal.other_income_rate` | 연금외수령 기타소득 15% | 소득세법 §129 ①6 나 |

**세액공제 한도의 적용 순서가 중요하다.** 연금저축 600만원 한도를 먼저 적용한 뒤 합산 900만원을 적용한다. 그래서 IRP만 있으면 900만원 전액이 공제 대상이지만, 연금저축만 있으면 최대 600만원이다. 이 순서를 뒤집으면 "연금저축 900만원 납입 시 900만원 공제"라는 틀린 답이 나온다. `pension.credit.limit.combined.value.ordering`에 명시해 두었다.

**종신계약 세율은 2026-01-01부터 4% → 3%로 인하되었다.** 국세청 안내 페이지가 이 변경을 명시하고 있고, 현행 조문도 3%다. 2025년 이전 기준으로 만든 자료를 그대로 옮기면 여기서 틀린다. 룰셋의 `change_note`에 적어 두었다.

### 3.2 ISA (7건)

| id | 내용 | 근거 |
|---|---|---|
| `isa.eligibility` | 19세 이상 거주자, 또는 15세 이상 + 직전 과세기간 근로소득 보유 | 조특법 §91조의18 ①1·2 |
| `isa.tax_free_limit` | 400만원(직전 총급여 5,000만원 이하 **또는** 직전 종합소득금액 3,800만원 이하) / 그 외 200만원 | 조특법 §91조의18 ② |
| `isa.excess.separate_tax_rate` | 초과분 9% 분리과세, 종합소득 합산 제외 | 조특법 §91조의18 ① |
| `isa.account.requirements` | 1명당 1계좌, 계약기간 3년 이상, 총 납입한도 1억원 | 조특법 §91조의18 ③ |
| `isa.contribution.annual_limit` | 연 2,000만원, 미납입분 이월 가능 (**교차확인만 — 3.4절**) | 조특법 §91조의18 ③5 |
| `isa.net_income.loss_offset` | 계좌 내 이익 − 손실 = 순소득 기준 과세 | 조특법 §91조의18 ⑤ |
| `isa.early_termination.clawback` | 3년 전 해지 시 감면세액 추징, 부득이한 사유 제외 | 조특법 §91조의18 ⑦ |

**서민형 판정은 "또는"이다.** 총급여 5,000만원 이하 **또는** 종합소득금액 3,800만원 이하 중 하나만 충족하면 된다. "그리고"로 구현하면 서민형 대상자를 일반형으로 떨어뜨린다.

**서민형 판정 기준연도는 "직전" 과세기간**이다. 반면 연금계좌 세액공제율은 **"해당" 과세기간** 기준이다. 두 계좌의 기준연도가 다르다 — 같은 사용자가 같은 화면에서 두 소득 기준을 각각 답해야 할 수 있고, 입력 폼 설계에 영향을 준다(`product-planner`·`designer`가 읽어야 할 사항).

### 3.3 공통 (1건)

`tax.local.personal_income_surtax` — 개인지방소득세는 소득세액의 10%(지방세법 §103조의13). 시중에서 흔히 쓰는 16.5% / 13.2% / 9.9% / 5.5%는 전부 여기서 나온 실효율이다.

**엔진에 실효율을 상수로 박지 말 것.** 소득세율 하나가 바뀌면 실효율 표 전체를 손으로 고쳐야 하고, 그때 한 칸을 빠뜨리는 것이 이 제품의 전형적 실패 경로다. 룰셋에는 국세 세율만 두고 엔진이 `× 1.1`을 하도록 했다. 참고용 표는 `derived_effective_rates`에 넣되 `engine_note`로 사용을 금지해 두었다.

### 3.4 신뢰도가 한 단계 낮은 규칙 하나

`isa.contribution.annual_limit`(연 2,000만원 · 이월 가능)은 조문 원문을 직접 읽지 못했다. 조특법 §91조의18 ③5는 "연간 납입한도가 다음의 계산식에 따른 금액일 것"이라고만 쓰고 계산식이 **이미지로** 실려 있다. 다음 두 가지로 교차확인했다.

1. 금융투자협회 「투자중개형 개인종합자산관리계좌 실무지침」 — 연 2,000만원, 미불입액 다음 연도 이월 가능, 총 1억원.
2. 재정경제부 「2026년 세제개편안」이 **현행 제도를** "연간 납입한도 미납입분 이월 가능"으로 기술하고 이를 폐지 대상으로 삼은 점.

정부 문서가 현행 제도를 그렇게 서술했다는 사실이 두 번째 근거의 힘이다. 그래도 1차 조문 확인은 아니므로 규칙에 `confidence: "corroborated"`와 `verification_note`를 달았다. 게이트 1 이전에 시행령 원문 확인을 권고한다.

## 4. 룰셋에 넣지 않은 것과 그 이유

**출처를 확인하지 못한 숫자를 채워 넣는 것이 이 유닛이 저지를 수 있는 최악의 행동이므로, 아래는 전부 뺐다.**

| 항목 | 왜 뺐는가 |
|---|---|
| 연금수령한도 산식 | 시행령 §40조의2 ③3의 계산식이 조문에 이미지로 실려 원문 확인 불가 |
| 이연퇴직소득 연금수령 감면율(70% / 60%) | 조문과 국세청 안내의 구간 경계가 엇갈림 — 5절 참조 |
| ISA 금융소득종합과세자 배제 요건 | 실무상 배제는 확실하나 근거 조항을 특정하지 못함 |
| ISA 부득이한 사유(특별중도해지) 목록 | 시행령 원문 미확인 |
| ISA 농어민 400만원 적용 | 조문상 별도 호 존재 여부 미확인 |
| ISA 가입 일몰(가입 기한) | 조특법 §91조의18 ① 원문에서 기한 조항을 찾지 못함. 현행법에 일몰이 있는지 자체가 불명확 |
| 연금소득공제(최대 900만원) 산식 | 인출 단계 계산용이고 A3 가정상 범위 밖 |
| 일반 ISA 5년 제한 · 이월 폐지 | 정부 문서 원문 미확인, 언론 보도만 존재 (5절) |
| 생산적금융 ISA 청년 소득공제 세부요건 | 같은 이유 (5절) |

## 5. 해석·확인이 갈리는 쟁점 (관리자 판단 필요)

### 쟁점 1 — 이연퇴직소득 연금수령 시 감면율의 구간 경계

- **읽기 A (법 조문):** 소득세법 §129 ①5의3 — 실제 수령연차 **10년 이하 70%**, **10년 초과 60%**.
- **읽기 B (국세청 안내 페이지 서술):** **10년 초과 20년 이하 70%**, **20년 초과 60%**.

두 읽기의 세액 차이가 크고(수령 초기 10년의 세율이 정반대로 갈린다), 어느 쪽도 확정하지 못했다. 룰셋에서 제외했다. A3 가정(납입 단계만 최적화)이 유지되면 영향이 없지만, 인출 단계를 다루기로 하면 반드시 먼저 해결해야 한다.

### 쟁점 2 — 생산적금융 ISA와 일반 ISA의 병행 보유

현행 조특법 §91조의18 ③은 "1명당 1개의 계좌만 보유할 것"을 요건으로 한다. 생산적금융 ISA가 별도 계좌 유형으로 신설될 때 일반 ISA와 동시 보유가 가능한지를 **어느 출처에서도 확인하지 못했다.**

- 병행 가능이면: 두 계좌에 어떻게 나눌지가 새로운 최적화 문제가 된다.
- 병행 불가면: "일반 ISA vs 생산적금융 ISA 택일" 비교 화면이 필요하다.

**설계가 완전히 달라지는 갈림길이다.** 게이트 1에서 판단하거나, 최소한 2단계 설계 전까지 확정해야 한다.

### 쟁점 3 — 일반 ISA 제도 정비의 내용

정부 상세본 목차에 "⑤ ISA 제도 정비(조특법)"가 있으나 내용을 정부 문서로 확인하지 못했다. 복수의 언론이 일관되게 보도하는 내용은 **계약기간을 최초 3년·최대 5년으로 제한**하고 **연간 납입한도 이월을 폐지**하며 **2027-01-01 이후 납입분부터 기존 가입자에게도 적용**한다는 것이다.

헌장의 "블로그나 기사만 근거인 규칙은 넣지 않는다"에 따라 규칙으로 만들지 않았다. 다만 사실이라면 영향이 크다 — 현행 제도에서 "ISA 한도를 못 채워도 나중에 몰아 넣으면 된다"는 조언이 성립하는데, 이월이 폐지되면 그 조언이 틀린 조언이 된다. **개정안 원문(입법예고 또는 국회 제출안)이 공개되는 즉시 재조사가 필요하다.**

### 쟁점 4 — 정부안이 그대로 통과된다고 가정하지 말 것

2024년 정부 세법개정안의 **국내투자형 ISA 신설**(금융소득종합과세 대상자 가입 허용, 별도 분리과세)은 국회 심사에서 수직적 형평성 문제가 제기되며 **개정세법에 반영되지 않았다.** ISA 제도 변경은 정부안 단계에서 좌초한 전례가 있다.

따라서 제품이 "개정안 반영 시" 시나리오를 보여줄 때 **"정부안 단계이며 국회 통과 전"임을 화면에 명시해야 한다.** `2027-proposed.json`의 모든 규칙에 `bill_stage: "정부안"`을 달아 두었으니 엔진과 UI가 이 값을 그대로 읽어 표시하면 된다. (`designer`·`web-dev`가 읽어야 할 사항)

## 6. 개정 선행조사 (`2027-proposed.json`) — 6건

**발표:** 재정경제부 「2026년 세제개편안」, 2026-08-03.
**진행 단계:** 정부안. 입법예고를 거쳐 2026-09-03 이전 정기국회 제출 예정 → 연말 국회 심의 → 공포 → 2027-01-01 시행 예정.

| id | 내용 |
|---|---|
| `proposed.productive_isa.introduction` | 생산적금융 ISA 신설 — 이자·배당소득 **전액** 비과세(한도 없음) |
| `proposed.productive_isa.contribution_limit` | 연 2,000만원 · 총 2억원 |

| `proposed.productive_isa.pension_transfer.credit_extra_limit` | 연금계좌 세액공제 추가한도 대상에 생산적금융 ISA 전환금 추가 |
| `proposed.productive_isa.rural_special_tax_exemption` | 생산적금융 ISA에 대한 농어촌특별세 비과세 |

**정부 보도자료의 첨부 PDF(개조식·상세본·문답자료)가 텍스트 추출이 되지 않아** 현행/개정안 대비표를 원문으로 읽지 못했다. 위 6건은 정부 문서에서 직접 확인된 문장(국가전략포털이 상세본 본문을 인용한 부분)과 상세본 목차 항목명에 근거한다. 값을 확인하지 못한 필드는 **채우지 않고 `null`로 두고 `unverified` 사유를 적었다.** 특히 `proposed.productive_isa.youth_income_deduction`은 공제율 10%만 확인되고 대상 연령·소득요건·공제한도가 전부 미확인이므로, **엔진이 이 규칙으로 금액을 산출해서는 안 된다**고 규칙 안에 명시했다.

## 7. 다음 단계 유닛에게 넘기는 사항

- **`calc-engine-dev`** — (a) 세액공제 한도는 연금저축 600 → 합산 900 순서로 적용한다. (b) 지방소득세는 룰셋의 소득세율에 `× 1.1`로 계산한다. 실효율 상수를 만들지 않는다. (c) 룰셋의 `value.type`은 `bracket` / `annual_limit` / `rate` / `threshold` / `elective` / `requirements` / `eligibility` / `clawback` / `computation` / `surtax` / `additional_limit` / `limit_extension` / `exemption` / `income_deduction` / `contribution_limit` 15종이다. 2단계에서 인터페이스를 고정할 때 이 목록을 대조해 달라. (d) `value` 안에 `unverified` 또는 `confidence` 필드가 있는 규칙은 결과 화면에 불확실성 표시가 필요하다.
- **`product-planner`** — ISA 서민형은 **직전** 과세기간 소득, 연금 세액공제는 **해당** 과세기간 소득으로 판정한다. 입력 항목 설계에 반영이 필요하다.
- **`designer`·`web-dev`** — 개정예고 규칙은 `bill_stage`를 그대로 표시해야 한다. "정부안(국회 통과 전)"임이 화면에서 드러나지 않으면 사용자가 확정 제도로 오해한다.
- **4단계의 나 자신** — 골든 케이스에 반드시 넣을 경계값: 종합소득금액 4,500만원 / 총급여 5,500만원 정확히, 직전 총급여 5,000만원 정확히, 직전 종합소득금액 3,800만원 정확히, 연금저축 단독 900만원 납입(600만원만 공제), 사적연금 1,500만원 정확히, 만 55세 생일 전후, 가입 5년 경과 직전·직후, ISA 3년 만기 직전 해지.
