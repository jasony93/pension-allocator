# 1단계 발견 — 제품 요구사항

**개정 이력.** 게이트 2 조건부 승인 후속 조치로 이 문서를 다시 연다. 화면 구조를 좌우 분할 통합 화면으로 확정했고(D8, 반영), 입력 `투자 성향`을 `자금 사용 시점`으로 대체했으며(D10, 반영), `screens.md`·`engine-interface.md`와 대조해 입력 항목을 갱신했다. 이전에 열려 있던 ISA 유형 기본값·투자 성향의 계산 변수 여부·소득 기준연도 상이·세무사법 문구 정책 질문은 게이트 1·2에서 각각 해소되어 `open_questions`에서 뺐다(각각 designer의 기본값 확정, D10, designer의 조건부 필드 설계, 헌장 반영으로 해소).

**게이트 2 마무리 개정.** 관리자가 직전 라운드의 `open_questions` 네 건을 모두 판정했다 — 전환 목적지는 화면에 반영 지시(변경 없음), 청년 자기신고 등 선택 입력 4개는 1차 출시에서 아예 묻지 않기로 확정(2절 반영), 개정안 다년도 차감 입력 미포함 가정은 승인(변경 없음), 연금계좌 보유기간 미입력 판단은 승인하되 리스크 기록을 지시(2절 반영). 이 라운드에서 새로 남은 `open_questions`는 없다.

**게이트 4 후속 개정(2026-08-09).** 게이트 4에서 `qa`가 AC 6·31을 미검증으로 남겼다(구현 `blockedPanel`은 존재·정확하나 현재 룰셋으로 그 상태에 도달할 수 없어 실행하지 못했다). 관리자 소집으로 `tax-domain`이 재확인한 결과(`tax-rules-report.md` 10절), **연금저축·IRP에는 세법상 최소 가입 연령 요건이 없다** — ISA만 조특법 §91조의18로 연령 요건이 있다. 즉 AC 6·31이 예로 든 "최소 가입 연령 미만 → (전체) 계산 불가"는 세법상 존재하지 않는 경로였다. 이 개정에서 2절 나이 항목, 4절 화면 상태 표, 6절 AC 6·31을 실제로 일어날 수 있는 상태(ISA만 부분 배제)에 맞게 고쳤다. `blockedPanel` 코드는 관리자 결정으로 남겨 두며, AC 31은 삭제하지 않고 "현재 룰셋 구조상 도달 불가"로 명시해 남긴다 — 향후 배제 규칙이 늘어 전체 차단 경로가 생기면 그때 검증 대상이 되도록 하기 위함이다. AC 개수(34개)는 변하지 않았다.

## 1. 타깃 사용자

**대상 확정(게이트 1 D2).** 1차 출시는 근로소득자만 다룬다. 종합소득자(자영업자·프리랜서 등)는 비범위로 확정됐다 — 세액공제율 구간 기준이 근로소득자(총급여 기준)와 종합소득자(종합소득금액 기준)에서 다르게 적용되어, 한쪽만 다루면 계산 분기와 오류 여지가 줄어든다는 것이 근거다(`docs/org/gate-decisions.md` D2). 확장은 이후 단계에서 별도로 검토한다.

**누구인가.** ISA·IRP·연금저축 중 최소 하나 이상을 이미 보유했거나 올해 안에 신규 가입을 고려 중인 근로소득자. 절세 계좌라는 개념 자체는 알고 있지만, "이번 달 남는 돈을 어느 계좌에 얼마씩 넣어야 세금을 가장 많이 아끼는지"를 계산하는 일이 번거로워 방치하거나 어림짐작으로 납입하는 사람.

**지금 이 문제를 어떻게 해결하고 있는가.**

- 네이버 블로그·유튜브의 일반론적 가이드("연금저축 먼저 채우고 IRP는 나중에" 같은 경험칙)를 읽고 스스로 판단한다. 자기 소득·나이·기존 납입액에 맞춘 계산이 아니라서 오차가 크다.
- 세액공제 계산기(예: 쿼터백연금연구소, 이지론, taxcalc.co.kr 등)에 **이미 자신이 정한 납입액**을 넣어 환급액만 확인한다. "얼마를 넣을지" 자체는 계산기가 정해주지 않는다.
- 증권사·은행 상담 창구나 챗봇에 문의한다. 특정 상품 가입 권유로 이어지는 경우가 많고, 계좌 간 배분을 중립적으로 비교해주는 경우는 드물다.
- 아무 계산 없이 연금저축 한도(연 600만원)만 우선 채우고 IRP·ISA는 미루거나 손대지 않는 경우가 흔하다(2절 경쟁 조사 참고).

## 2. 입력 항목 목록

`자금 사용 시점`은 게이트 2 D10으로 `투자 성향`을 대체한 입력이다. 계산 변수가 아니라 배분안의 제시 순서와 경고를 정하는 입력이며, 필드명·선택지는 인터페이스 소유자 `calc-engine-dev`가 `engine-interface.md`에서 확정한 `profile.fund_use_horizon`을 그대로 쓴다. 이 문서도 화면도 선택지 이름에 실제 연수를 넣지 않는다 — 실제 연수는 엔진이 룰셋에서 읽어 결과로 내보낸다.

| 항목명 | 자료형 | 필수/선택 | 허용 범위 | 모를 때의 기본값 처리 |
|---|---|---|---|---|
| 나이 | 정수 (만 나이) | 필수 | 0 이상. ISA는 세무 유닛이 정의하는 가입 연령 요건 미만이면 배분 대상에서 제외된다(6절 AC 6). 연금저축·IRP는 세법상 최소 가입 연령 요건이 없어 나이로는 배제되지 않는다(`tax-rules-report.md` 10절) | 기본값 없음. 미입력 시 다음 단계로 진행 불가 |
| 총급여액(해당 과세연도) | 숫자, 원 단위 | 필수 | 0 이상 | 기본값 없음. 정확한 값을 모르면 근로소득 원천징수영수증 또는 최근 급여명세 기준 추정치를 입력하도록 안내 문구 표시 |
| 직전 과세기간 총급여액 | 숫자, 원 단위 | 선택 | 0 이상 | **null이면 해당 과세연도 값과 같다고 간주**하고, 그 가정을 결과 화면에 명시한다. designer가 3.3절에서 체크박스로 조건부 노출을 설계했다 — 두 값이 같은 사용자에게는 필드를 하나로 유지한다 |
| **자금 사용 시점** (`profile.fund_use_horizon`) | 문자열 열거형 — `within_isa_lock_in` / `before_pension_age` / `at_or_after_pension_age` / `unknown` | **필수** | 네 값 중 하나 | **기본값 없음.** 모르면 `unknown`을 명시적으로 선택한다 — 사용자가 밝히지 않은 사정을 서비스가 대신 정하지 않는다. 계좌별 배분 금액·예상 절세액에는 영향이 없고, 배분안의 제시 순서와 중도 인출·해지 경고에만 영향을 준다 |
| 월 납입 여력 | 숫자, 원 단위 | 필수 | 0 이상 | 기본값 없음. "지금 당장 배분 가능한 여윳돈" 기준으로 입력하도록 안내 |
| 연금저축 기납입액(해당 과세연도 누적) | 숫자, 원 단위 | 필수 | 0 이상 | 계좌가 없으면 0 입력 |
| IRP 기납입액(해당 과세연도 누적) | 숫자, 원 단위 | 필수 | 0 이상 | 계좌가 없으면 0 입력 |
| ISA 계좌 보유 여부 | 예/아니오 | 필수 | — | 없음 — 예/아니오 중 하나를 선택해야 한다. "아니오"면 신규 가입을 전제로 잔여 한도를 계산하고 그 사실을 결과에 표시한다. 누적 납입액이 0인 것과 계좌 자체가 없는 것은 다른 사실이므로 별도 항목으로 받는다 |
| ISA 계좌 유형 | 단일 선택 (일반형 / 서민형) | ISA 보유 시 선택 | 세무 유닛이 정의하는 유형 중 하나 | **모르면 "일반형"을 기본 선택값으로 지정한다 — designer가 3.1절 화면에서 확정했다.** 그 가정은 결과 화면의 가정 목록에 표시된다 |
| ISA 누적 납입액(가입 이후 총액) | 숫자, 원 단위 | ISA 보유 시 필수 | 0 이상 | ISA 미보유면 0. 총 납입한도 판정에 쓴다 |
| ISA 당해연도 누적 납입액 | 숫자, 원 단위 | ISA 보유 시 필수 | 0 이상, 가입 이후 총액 이하 | ISA 미보유면 0. 해당 과세연도의 잔여 납입 한도 판정에 쓴다. 가입 이후 총액과 다른 값이다 |
| ISA 만기 전환 여부 | 단일 선택 (예 / 아니오) | 선택 — ISA 보유일 때만 화면에 노출 | 예 / 아니오 | 기본값 "아니오". ISA 미보유면 이 항목 자체를 표시하지 않는다 |
| ISA 만기 전환 금액 | 숫자, 원 단위 | ISA 만기 전환 여부가 "예"일 때 필수 | 1 이상, ISA 누적 납입액(가입 이후 총액) 이하 | 전환 여부가 "아니오"면 입력 자체를 표시하지 않는다. 이 금액은 월 납입 여력의 배분 예산에 포함되지 않는다 |
| 전환 목적지 | 단일 선택 — IRP / 연금저축 | ISA 만기 전환 여부가 "예"일 때 선택 | 둘 중 하나 | **null이면 IRP로 간주**한다. 목적지에 따라 적용되는 단독 한도가 달라 결과가 달라진다. 게이트 2 후속 판정으로 화면에 반영이 확정됐다(designer에게 지시됨) |
| 직전 과세기간 전환 세액공제 적용액 | 숫자, 원 단위 | 선택 | 0 이상, 세무 유닛이 정의하는 연간 추가한도 이하 | 모르거나 해당 없으면 0 (작년에 이 추가공제를 받지 않았다고 간주) |

**입력에 넣지 않기로 한 것.** 해당 과세연도에 남은 납입 개월수는 사용자에게 묻지 않는다. 계산 시점의 현재 날짜에서 자동으로 셈해 웹 화면이 채워 넣는 값이며, 사용자가 직접 판단할 정보가 아니다.

**1차 출시에서 묻지 않기로 확정한 선택 입력 4개(게이트 2 후속 판정).** 아래 넷은 엔진이 선택 필드로 받는 값이지만, 화면에서는 묻지 않는다.

- ISA 가입경과연수
- 재형저축·장기집합투자증권저축 계약금액 총액
- 금융소득종합과세 대상 여부(최근 3개 과세기간 중 1회 이상)
- 청년 자기신고 여부

**근거.** 이번 개정에서 엔진 인터페이스 대조로 입력 항목이 8개 늘어 15개 안팎이 됐는데, biz-model의 1순위 지표는 계산 완료율(목표 35%)이다. 입력을 늘리면 그 지표가 무너진다. 위 넷은 모두 값이 없어도 엔진이 안전한 기본값(가장 보수적인 값 또는 "적용하지 않음")으로 계산을 계속하고 그 사실을 안내로 낼 수 있는 항목이라, 화면에서 아예 묻지 않고 결과의 가정 블록(`[4-E]` `AssumptionBlock`)에 "묻지 않은 항목"으로 드러내는 방식을 관리자가 designer의 제안대로 승인했다. 완료율과 정직함을 동시에 지키는 절충이다. 이것들은 "화면에서 조건부로 노출되는 선택 입력"이 아니라 "1차 출시에서 아예 묻지 않는 항목"이라는 점에서, 여전히 조건부로 화면에 노출되는 직전 과세기간 총급여액(designer 3.3절 체크박스)이나 ISA 만기 전환 관련 항목과는 다르다.

**연금계좌 가입경과연수를 묻지 않는 것과 남은 리스크 — v2 검토 항목.** 연금계좌 가입경과연수도 묻지 않는다 — 인출 단계 자체가 v2로 연기되어(게이트 1 D3) 지금은 중도인출 경고의 근거로만 쓰이고, 근거 표시로 충분하다고 판단했다. 다만 calc-engine-dev가 지적한 리스크를 기록해 둔다 — 이 값이 없으면 **고령 신규 가입자**(연금계좌를 늦게 개설해 보유기간 요건에 걸릴 수 있는 사용자)에게 나가는 중도인출 경고가 실제보다 약하게 표시될 수 있다. 지금은 입력을 늘리지 않는 쪽을 택했지만, v2에서 인출 단계를 다룰 때 이 입력을 추가할지 다시 검토해야 한다.

**ISA 만기 전환 항목에 대한 근거.** 게이트 1 D3에서 ISA 만기 자금을 연금계좌(IRP·연금저축)로 전환할 때의 추가 세액공제가 범위에 들어왔다(`docs/org/gate-decisions.md` D3). 해당 규칙(`pension.credit.isa_transfer.extra_limit`)은 "전환금액 × 세무 유닛이 정의한 비율"과 "세무 유닛이 정의한 연간 상한"을 비교해 둘 중 작은 값을 추가 한도로 더하며, 직전 과세기간에 이미 적용된 금액이 있으면 그만큼을 상한에서 차감한다. 위 입력 항목들은 이 계산에 필요한 최소 입력이다. 세법상 정확한 비율·상한 수치는 이 문서에서 다루지 않고 `data/tax-rules/`의 해당 규칙을 계산 엔진이 참조한다.

세법상 정확한 한도·공제율·구간 수치는 이 문서에서 다루지 않는다. 모두 tax-domain 유닛이 `data/tax-rules/`에 출처와 함께 정의한 값을 계산 엔진이 참조한다.

## 3. 유저 플로우

**게이트 2 D8로 화면 구조가 바뀌었다.** 소유자가 확정한 구조는 랜딩·입력·결과가 분리된 별도 화면이 아니라 **좌측 입력 / 우측 결과의 좌우 분할 한 화면**이며, 결과는 실시간으로 반영된다. 아래 유저 플로우는 이 구조를 기준으로 한다. 이전 버전(3화면 분리)은 폐기됐다.

1. **진입** — 사용자가 검색·공유 링크 등으로 통합 화면에 도달한다. 이 시점에는 필수 입력이 비어 있으므로 결과 영역은 **"무엇을 더 입력하면 결과가 나오는지"를 보여주는 입력 부족 상태**로 시작한다. 이것이 첫 진입의 기본 상태다.
2. **입력** — 좌측 패널에서 2절의 항목을 채운다. ISA 계좌 보유 여부를 "예"로 두면 ISA 관련 항목이, 그중 만기 전환 여부를 "예"로 두면 전환 관련 항목이 추가로 나타난다. 각 항목은 채우는 즉시 검증되고, 오류가 있으면 그 항목 옆에 바로 표시된다.
3. **실시간 결과 확인** — 필수 항목이 모두 유효한 값으로 채워지는 순간, 별도의 제출 동작 없이 우측 결과 영역이 자동으로 결과 상태로 바뀐다. 결과는 기본안 하나와 대안 0~2개를 함께 비교하는 형태로 나온다.
4. **입력 수정과 재계산** — 이미 결과가 나온 뒤에도 왼쪽 값을 바꾸면 오른쪽 결과가 그 값으로 다시 계산되어 갱신된다. 별도의 "다시 계산" 화면으로 이동하지 않는다.
5. **(선택) 대안 비교** — 결과 영역에서 대안을 선택하면 기본안 대신 그 대안의 세부 내용을 살펴본다.
6. **(선택) 저장·공유** — 결과를 이미지 등으로 저장하거나 공유한다. 입력값(나이·소득 등 개인정보)은 공유 데이터에 포함하지 않는다. (범위 확정 근거: biz-model의 `demand-validation-plan.md`가 이 기능에 수요 판정 지표 3 "결과 저장·공유율"(목표 12% 이상)을 걸어 뒀다. 빠지면 그 지표를 측정할 수 없으므로 화면 목록에서 유지한다.)
7. **(선택) 초기화** — 전체 입력을 지우고 1번 상태로 되돌린다.

## 4. 화면 목록

**게이트 2 D8 반영.** 별도의 랜딩·입력·결과 페이지가 아니라 하나의 통합 화면이며, 이전에 화면으로 나눴던 것들은 그 화면 안의 상태로 재구성됐다.

| 화면명 | 목적 |
|---|---|
| 통합 작업 화면 (좌측 입력 / 우측 결과) | 하나의 화면 안에서 값을 입력하고 배분 결과를 실시간으로 확인한다. 별도의 랜딩·입력·결과 페이지로 나뉘지 않는다 |

이 화면은 아래 상태를 오간다. 별도 화면이 아니라 같은 화면의 결과 영역이 갖는 상태다.

| 상태 | 목적 |
|---|---|
| 입력 부족 (첫 진입 기본 상태) | 서비스가 무엇을 해주는지와, 결과를 보려면 무엇을 더 입력해야 하는지를 보여준다 |
| 결과 | 계좌별 추천 납입액, 예상 절세액, 그 근거, 대안 비교를 보여준다 |
| 계산 불가 | 세 계좌가 동시에 계산 불가능해지는 입력 상태를 설명하고 복귀 경로를 제공한다. 현재 룰셋 구조상 이 상태에 도달하는 입력 조합은 없다 — 6절 AC 31 참고 |

**카피 방향과 채널 조사 대조(유지).** growth의 `channel-research.md`가 제시한 1순위 채널(네이버 블로그 오가닉 검색 SEO)은 "내가 절세 계좌를 제대로 쓰고 있는지 점검하려는 확인 욕구"를 동기로 본다. 이 문서가 애초에 가정했던 "검색 유입이 주력"이라는 전제 및 1절의 타깃 동기(어림짐작으로 납입해 오차가 큰 문제를 확인하고 싶은 사람)와 일치한다. 화면 구조가 통합형으로 바뀌었어도 첫 진입 시 보여줄 메시지의 방향은 바뀌지 않는다.

## 5. 결과 화면이 답해야 할 질문

- 지금 가진 월 납입 여력을 ISA·IRP·연금저축에 각각 얼마씩 넣어야 하는가?
- 그렇게 배분했을 때 올해 예상 절세 효과(세액공제 환급 추정치 등)는 얼마인가?
- 왜 이 배분인가 — 어떤 한도·조건 때문에 이렇게 나뉘었는가?
- 월 납입 여력이 세 계좌의 한도 합계보다 적어서 다 채우지 못한다면, 무엇을 우선 채워야 가장 이득인가?
- 반대로 여력이 한도 합계보다 많다면, 한도를 넘는 금액은 어떻게 되는가(추천 배분에서 제외된다는 사실)?
- 기존에 이미 납입한 금액은 이번 추천에 어떻게 반영되었는가?
- ISA 만기 자금을 연금계좌로 전환하면(전환 여부를 "예"로 입력한 경우) 추가로 늘어나는 세액공제 한도는 얼마이고, 그만큼 추천 배분이 어떻게 달라지는가?
- 기본안 말고 다른 배분(대안)은 무엇이 다르고, 절세액이 얼마나 차이 나는가?
- **자금 사용 시점에 대한 답이 배분 금액 자체를 바꾸는가, 아니면 다른 것을 바꾸는가?**(게이트 2 D10) — 바꾸지 않는다는 사실과, 대신 무엇이 바뀌는지(배분안 순서·경고)를 사용자가 오해 없이 알아야 한다.
- 지금 나온 배분을 자금 사용 시점보다 이르게 인출·해지하면 어떤 불이익이 있을 수 있는가?

## 6. 수용 기준(AC)

**게이트 2 D8 반영.** "계산하기 버튼" 개념은 사라졌다 — 필수 항목이 채워지는 즉시 결과가 실시간으로 나온다. 아래 AC는 통합 화면(좌측 입력 / 우측 결과)을 기준으로 다시 썼다.

**입력**

- 사용자가 나이·총급여액·자금 사용 시점·월 납입 여력 중 하나라도 비워두면, 결과 영역은 결과 상태로 전환되지 않고 입력 부족 상태를 유지한다.
- 사용자가 나이에 정수가 아닌 값(소수, 문자)을 입력하면, 해당 필드는 오류를 표시하고 그 값을 계산에 사용하지 않는다.
- 사용자가 총급여액·월 납입 여력·기납입액 중 하나에 음수를 입력하면, 해당 필드는 오류를 표시한다.
- 사용자가 자금 사용 시점을 선택하지 않으면, 결과 영역은 결과 상태로 전환되지 않는다 — 이 항목에는 기본 선택값이 없다.
- 사용자가 연금저축·IRP 기납입액과 ISA 관련 금액 항목을 입력하지 않고 진행하면, 해당 항목은 0으로 간주되고 진행을 막지 않는다.
- 사용자가 나이에 ISA 가입 연령 요건(세무 유닛이 정의) 미만 값을 입력하면, 결과 영역은 결과 상태를 유지하며 ISA는 배분 대상에서 제외되고 그 사유와 근거 조항이 함께 표시된다. 연금저축·IRP에는 세법상 최소 가입 연령 요건이 없어(`tax-rules-report.md` 10절) 이 조건으로는 배제되지 않고 정상적으로 배분에 포함된다.
- 사용자가 ISA 계좌 보유 여부를 "아니오"로 두면, ISA 유형·누적 납입액·전환 관련 입력이 화면에 나타나지 않는다.
- 사용자가 ISA 만기 전환 여부를 "예"로 선택하고 전환 금액을 비워두거나 ISA 누적 납입액(가입 이후 총액)을 초과하는 값을 입력하면, 결과 영역은 갱신되지 않고 해당 항목에 오류가 표시된다.
- 사용자가 ISA 만기 전환 여부를 "아니오"로 두거나 선택하지 않으면, 전환 금액·전환 목적지·직전 과세기간 적용액은 계산에 반영되지 않는다.
- 사용자가 필수 항목을 모두 유효한 값으로 채우면, 별도의 제출 동작 없이 결과 영역이 자동으로 결과 상태로 전환된다.
- 사용자가 결과가 나온 뒤에 입력값을 변경하면, 결과 영역은 새 값으로 다시 계산되어 갱신된다.

**결과 — 배분과 근거**

- 결과가 나오면, 결과 영역은 ISA·IRP·연금저축 세 계좌 각각에 대한 기본안의 추천 납입액을 숫자로 표시한다.
- 결과 영역은 기본안 정확히 하나와 대안 0~2개를 함께 제시한다. 대안이 하나도 없으면 오류로 표시하지 않고 비교 대상이 없다는 사실만 안내한다.
- 대안이 하나 이상 있으면, 각 대안이 기본안 대비 절세액에서 얼마나 차이 나는지 함께 표시한다.
- 어떤 배분안에도 "추천"·"최적"·"권장" 같은 단정적 표현을 쓰지 않는다. 기본안은 "기본"이라는 표시만 단다.
- 월 납입 여력이 세 계좌의 잔여 한도 합계보다 적으면, 결과 영역은 한도를 다 채우지 못했다는 사실과 이 배분안이 무엇을 우선했는지를 함께 표시한다.
- 월 납입 여력이 세 계좌의 잔여 한도 합계 이상이면, 결과 영역은 세 계좌 모두 잔여 한도까지 채우는 배분을 제시하고 남는 금액이 있다는 사실을 표시한다.
- 사용자가 기존 납입액(연금저축·IRP·ISA)을 입력했으면, 추천 배분은 각 계좌의 한도에서 기존 납입액을 제외한 잔여 한도 내에서만 계산되어 표시된다.
- 사용자가 ISA 만기 전환 여부를 "예"로 입력하면, 결과 영역은 전환으로 늘어난 연금계좌 세액공제 추가 한도를 별도 항목으로 표시하고, 그 한도가 연금저축·IRP 추천 배분에 반영되었음을 보여준다.
- 사용자가 ISA 만기 전환 여부를 "아니오"로 입력하거나 ISA를 보유하지 않으면, 전환 관련 추가 한도 항목은 표시되지 않는다.

**결과 — 자금 사용 시점의 효과 (게이트 2 D10)**

- 사용자가 자금 사용 시점 선택을 바꾸면, 결과 영역의 계좌별 배분 금액과 예상 절세액은 값이 그대로 유지되고, 배분안의 제시 순서와 경고 표시만 달라진다.
- 배분액이 0보다 큰 연금저축 또는 IRP가 있고, 자금 사용 시점이 "ISA 의무가입기간 내" 또는 "연금 수령 개시 연령 이전"이면, 결과 영역은 해당 계좌에 중도 인출 시 불이익이 있을 수 있다는 경고를 근거 조항과 함께 표시한다.
- 배분액이 0보다 큰 ISA가 있고, 자금 사용 시점이 "ISA 의무가입기간 내"이면, 결과 영역은 ISA 의무가입기간을 채우지 못하면 감면세액이 추징될 수 있다는 경고를 근거 조항과 함께 표시한다.
- 자금 사용 시점을 "모르겠음"으로 선택하면, 위 경고들은 확정적 경고가 아니라 참고 안내 수준으로 표시된다.
- 자금 사용 시점이 "연금 수령 개시 연령 이후"이면, 위 경고들은 표시되지 않는다.
- 위 경고는 금액을 포함하지 않는다 — 중도 인출 시 실제로 얼마를 더 내는지는 계산하지 않는다(비범위, 7절).

**결과 — 고지와 중립성**

- 결과 영역은 "세법 계산 예시이며 투자·세무 자문이 아님" 고지 문구를 예외 없이 표시한다.
- 결과 영역은 특정 금융상품명·금융사명을 표시하지 않는다.
- 결과 영역은 사용자가 입력한 나이·소득·기존 납입액 등 개인 값을 서버로 전송하지 않고 브라우저 내 계산 결과만 표시한다.
- 사용자가 "저장·공유"를 실행하면, 생성되는 결과물(이미지 등)에는 나이·소득·월 납입 여력·기존 납입액 등 개인 식별 가능 입력값이 포함되지 않는다.

**계산 불가**

- 세 계좌가 모두 동시에 계산 불가능해지는 입력 조합이 발생하면, 결과 영역은 결과가 아닌 계산 불가 상태로 전환되고 사유와 복귀 경로(해당 입력으로 이동)를 함께 보여준다. **현재 룰셋 구조상 이 조건에 도달하는 입력 조합은 존재하지 않는다** — 연금저축·IRP에는 세법상 최소 가입 연령·소득 요건이 없어 나이만으로는 배제되지 않고, 이 룰셋 범위의 다른 배제 규칙(ISA 연령·ISA 금융소득종합과세)도 연금 두 계좌를 배제하지 않는다(`tax-rules-report.md` 10절). 이 AC는 향후 배제 규칙이 늘어 세 계좌가 동시에 막히는 조합이 생길 경우를 위해 남겨 두며, 현 룰셋 기준으로는 검증 대상 케이스가 없다는 뜻으로 판정한다(N/A로 판정하고, "부분"으로 계속 남기지 않는다).
- 세 계좌 중 일부만 계산이 불가능하면, 나머지 계좌에 대한 결과는 정상적으로 함께 보여준다(전체를 차단하지 않는다).

**비범위 검증**

- 어떤 상태에서도 로그인·회원가입을 요구하지 않는다.
- 어떤 상태에서도 광고나 유료 결제 유도 요소를 표시하지 않는다.

## 7. 비범위

- 종합소득자(자영업자·프리랜서 등) 전용 소득 입력 처리 — 1차 출시는 근로소득자(총급여 기준)만 다룬다(게이트 1 D2 확정, `docs/org/gate-decisions.md`).
- 부양가족 공제 등 연말정산의 다른 항목과의 통합 계산.
- 특정 금융상품·금융사 추천 또는 상품 비교·가입 연결.
- 로그인, 회원가입, 사용자 계정, 서버에 개인 입력값 저장.
- 여러 번의 계산 이력을 서버에 저장해 추적하는 기능.
- 모바일 네이티브 앱(반응형 웹만 다룬다).
- 유료 기능, 광고, 제휴 상품 노출 — 출시 버전은 수익화·광고가 없다(헌장 제품 원칙 7).
- 다년도·은퇴 시점까지의 복리 시뮬레이션 — 이번 버전은 당해 연도 최적 배분에 한정한다.
- ISA 만기 전환의 손익분기점·수수료 비교 시뮬레이션 — 전환 시 늘어나는 세액공제 한도 자체는 이번 범위에 포함됐지만(2절·게이트 1 D3), "전환하는 것이 유리한지"를 손익분기점·수수료로 따져주는 별도 시뮬레이션은 이번 범위에 포함하지 않는다.
- **연금 인출 단계 시뮬레이션(v2로 연기, 게이트 1 D3 확정)** — 연금수령한도 계산, 이연퇴직소득 감면율 적용 등 인출 단계에 필요한 계산은 이번 버전에서 다루지 않는다. 근거: 인출 계산에 필요한 두 수치 — 연금수령한도 산식(소득세법 시행령 §40조의2 ③3)과 이연퇴직소득 감면율(수령연차 구간) — 를 tax-domain이 1차 출처(조문 원문)로 확인하지 못했다(`tax-rules-report.md` 4절·5절 쟁점1). 출처 없는 규칙은 무효라는 제품 원칙 2에 따라, 이 두 수치가 출처와 함께 확정되기 전에는 인출 화면을 만들 수 없다.
- **중도 인출·중도 해지 시 실제로 얼마를 더 내는지의 금액 계산** — 인출 단계와 마찬가지로 v2. 이번 범위에서는 자금 사용 시점 입력에 따라 불이익이 있을 수 있다는 사실과 근거 조항만 결과에 알린다(6절 "결과 — 자금 사용 시점의 효과").
- 세무사·재무설계사 상담 연결.

## 8. 경쟁·유사 서비스 조사

| 서비스 | 무엇을 해주는가 | 무엇을 안 해주는가 |
|---|---|---|
| 쿼터백연금연구소 — 연금저축·IRP 세액공제 계산기 (qbr.co.kr/retirement-calc/tax-deduction) | 사용자가 직접 입력한 연금저축·IRP 납입액과 총급여를 받아 세액공제 환급액을 계산해 보여준다 | 사용자가 "얼마를 넣어야 하는지"는 정해주지 않는다. 입력값은 사용자가 이미 결정한 금액이라는 전제이고, ISA는 계산 범위에 없다 |
| 쿼터백연금연구소 — ISA→IRP 전환 계산기 (qbr.co.kr/retirement-calc/isa-irp) | ISA 만기 자금을 IRP·연금저축으로 전환할 때의 추가 세액공제와 손익분기점을 계산한다 | 세 계좌를 동시에 놓고 월 납입 여력을 배분하는 문제는 다루지 않는다. ISA 만기라는 단일 이벤트에 한정된 전환 시뮬레이션이며, 나이·투자 성향별 맞춤 배분은 제시하지 않는다 |
| 토스뱅크 — 연금저축·IRP 세액공제 안내 페이지 (tossbank.com/articles/pension-savings-tax-deduction) | 세액공제율·한도를 표와 고정 예시("총급여 5,200만원이면 148.5만원")로 설명하는 교육 콘텐츠를 제공한다 | 사용자가 자기 값을 입력해 결과를 받는 인터랙티브 기능이 없다. 모든 사람에게 같은 예시만 보여준다 |
| 뱅크샐러드 — 연금저축·IRP 세액공제 총정리 (banksalad.com) | 소득 구간별 세액공제율·환급액 표를 정리해 보여주는 정보성 글을 제공한다 | 계산기가 없다. 글 끝에서 "30개사 상품 비교"로 사용자를 유도해, 계좌 배분 문제를 상품 비교·가입 퍼널로 대체한다 |

**이 서비스가 다르게 하는 것 (한 문장).** 위 서비스들은 하나같이 사용자가 "얼마를 넣을지"를 이미 정했다는 전제에서 세액공제액을 계산해주거나(쿼터백 세액공제 계산기), 단일 이벤트(ISA 만기 전환)만 다루거나(쿼터백 전환 계산기), 계산 자체를 제공하지 않고 정보나 상품 비교로 안내한다(토스뱅크, 뱅크샐러드) — 이 서비스는 반대로 "월 납입 여력"이라는 하나의 예산만 입력받아, 나이·소득·자금 사용 시점·기존 납입 현황을 함께 고려해 ISA·IRP·연금저축 세 계좌에 얼마씩 나눠 넣을지 그 배분 자체를 산출해준다.
