# 1단계 발견 — 제품 요구사항

## 1. 타깃 사용자

**대상 확정(게이트 1 D2).** 1차 출시는 근로소득자만 다룬다. 종합소득자(자영업자·프리랜서 등)는 비범위로 확정됐다 — 세액공제율 구간 기준이 근로소득자(총급여 기준)와 종합소득자(종합소득금액 기준)에서 다르게 적용되어, 한쪽만 다루면 계산 분기와 오류 여지가 줄어든다는 것이 근거다(`docs/org/gate-decisions.md` D2). 확장은 이후 단계에서 별도로 검토한다.

**누구인가.** ISA·IRP·연금저축 중 최소 하나 이상을 이미 보유했거나 올해 안에 신규 가입을 고려 중인 근로소득자. 절세 계좌라는 개념 자체는 알고 있지만, "이번 달 남는 돈을 어느 계좌에 얼마씩 넣어야 세금을 가장 많이 아끼는지"를 계산하는 일이 번거로워 방치하거나 어림짐작으로 납입하는 사람.

**지금 이 문제를 어떻게 해결하고 있는가.**

- 네이버 블로그·유튜브의 일반론적 가이드("연금저축 먼저 채우고 IRP는 나중에" 같은 경험칙)를 읽고 스스로 판단한다. 자기 소득·나이·기존 납입액에 맞춘 계산이 아니라서 오차가 크다.
- 세액공제 계산기(예: 쿼터백연금연구소, 이지론, taxcalc.co.kr 등)에 **이미 자신이 정한 납입액**을 넣어 환급액만 확인한다. "얼마를 넣을지" 자체는 계산기가 정해주지 않는다.
- 증권사·은행 상담 창구나 챗봇에 문의한다. 특정 상품 가입 권유로 이어지는 경우가 많고, 계좌 간 배분을 중립적으로 비교해주는 경우는 드물다.
- 아무 계산 없이 연금저축 한도(연 600만원)만 우선 채우고 IRP·ISA는 미루거나 손대지 않는 경우가 흔하다(2절 경쟁 조사 참고).

## 2. 입력 항목 목록

| 항목명 | 자료형 | 필수/선택 | 허용 범위 | 모를 때의 기본값 처리 |
|---|---|---|---|---|
| 나이 | 정수 (만 나이) | 필수 | 0 이상, 세무 유닛이 정의하는 계좌별 최소 가입 연령 이상이어야 계산 가능 | 기본값 없음. 미입력 시 다음 단계로 진행 불가 |
| 총급여액(연간) | 숫자, 원 단위 | 필수 | 0 이상 | 기본값 없음. 정확한 값을 모르면 근로소득 원천징수영수증 또는 최근 급여명세 기준 추정치를 입력하도록 안내 문구 표시 |
| 월 납입 여력 | 숫자, 원 단위 | 필수 | 0 이상 | 기본값 없음. "지금 당장 배분 가능한 여윳돈" 기준으로 입력하도록 안내 |
| 투자 성향 | 단일 선택 (예: 안정형 / 중립형 / 공격형) | 필수 | 세 구간 중 하나 | 모르면 "중립형"을 기본 선택값으로 미리 지정해두고, 사용자가 원하면 변경 |
| 연금저축 기납입액(올해 누적) | 숫자, 원 단위 | 필수 | 0 이상 | 계좌가 없으면 0 입력 |
| IRP 기납입액(올해 누적) | 숫자, 원 단위 | 필수 | 0 이상 | 계좌가 없으면 0 입력 |
| ISA 납입액(누적, 계좌 존재 시) | 숫자, 원 단위 | 필수 | 0 이상 | 계좌가 없으면 0 입력 |
| ISA 계좌 유형 | 단일 선택 (일반형 / 서민형) | ISA 누적 납입액이 0보다 크거나 신규 가입을 고려할 때 필수 | 세무 유닛이 정의하는 유형 중 하나 | 모르면 "일반형"을 기본 선택값으로 지정 (open_questions 참고) |
| ISA 만기 전환 여부 | 단일 선택 (예 / 아니오) | 선택 — ISA 누적 납입액이 0보다 클 때만 화면에 노출 | 예 / 아니오 | 기본값 "아니오". ISA 누적 납입액이 0이면 이 항목 자체를 표시하지 않는다 |
| ISA 만기 전환 금액 | 숫자, 원 단위 | ISA 만기 전환 여부가 "예"일 때 필수 | 0 이상, ISA 누적 납입액 이하 | 전환 여부가 "아니오"면 입력 자체를 표시하지 않는다 |
| 직전 과세기간 전환 세액공제 적용액 | 숫자, 원 단위 | 선택 | 0 이상, 세무 유닛이 정의하는 연간 추가한도 이하 | 모르거나 해당 없으면 0 (작년에 이 추가공제를 받지 않았다고 간주) |

**ISA 만기 전환 항목에 대한 근거.** 게이트 1 D3에서 ISA 만기 자금을 연금계좌(IRP·연금저축)로 전환할 때의 추가 세액공제가 범위에 들어왔다(`docs/org/gate-decisions.md` D3). 해당 규칙(`pension.credit.isa_transfer.extra_limit`)은 "전환금액 × 세무 유닛이 정의한 비율"과 "세무 유닛이 정의한 연간 상한"을 비교해 둘 중 작은 값을 추가 한도로 더하며, 직전 과세기간에 이미 적용된 금액이 있으면 그만큼을 상한에서 차감한다. 위 세 입력 항목은 이 계산에 필요한 최소 입력이다. 세법상 정확한 비율·상한 수치는 이 문서에서 다루지 않고 `data/tax-rules/`의 해당 규칙을 계산 엔진이 참조한다.

세법상 정확한 한도·공제율·구간 수치는 이 문서에서 다루지 않는다. 모두 tax-domain 유닛이 `data/tax-rules/`에 출처와 함께 정의한 값을 계산 엔진이 참조한다.

## 3. 유저 플로우

1. **랜딩 진입** — 사용자가 검색·공유 링크 등으로 랜딩 화면에 도달한다.
2. **시작** — "시작하기"를 누르면 입력 화면으로 이동한다.
3. **입력** — 2절의 항목을 순서대로 또는 한 화면에서 입력한다. ISA 누적 납입액을 0보다 크게 입력하면 ISA 만기 전환 여부·전환 금액 항목이 추가로 나타난다. 필수 항목이 비어 있거나 허용 범위를 벗어나면 그 항목 옆에 즉시 오류를 표시한다.
4. **계산 요청** — 모든 필수 항목이 유효하면 "계산하기" 버튼이 활성화된다. 버튼을 누르면 브라우저 안에서 계산이 실행된다.
5. **결과 확인** — 결과 화면으로 이동해 계좌별 추천 납입액과 근거를 확인한다.
6. **(선택) 저장·공유** — 결과를 이미지·링크 등으로 저장하거나 공유한다. 입력값(나이·소득 등 개인정보)은 공유 데이터에 포함하지 않는다. (범위 확정 근거: biz-model의 `demand-validation-plan.md`가 이 기능에 수요 판정 지표 3 "결과 저장·공유율"(목표 12% 이상)을 걸어 뒀다. 빠지면 그 지표를 측정할 수 없으므로 화면 목록에서 유지한다.)
7. **(선택) 다시 계산** — 입력값을 바꿔 재계산한다. 이전 입력은 브라우저 세션 안에서만 유지된다.

## 4. 화면 목록

| 화면명 | 목적 |
|---|---|
| 랜딩 화면 | 이 서비스가 "정해진 예산을 계좌별로 어떻게 나눌지"를 계산해준다는 것을 첫 화면에서 바로 이해시키고 입력을 시작하게 한다 |
| 입력 화면 | 계산에 필요한 최소 정보(2절 항목, ISA 만기 전환 관련 항목은 조건부)를 정확한 값으로 받는다 |
| 결과 화면 | 계좌별 추천 납입액과 예상 절세액, 그 근거를 보여준다 |
| 오류·안내 화면(또는 인라인 상태) | 계산이 불가능한 입력 상태(예: 나이가 최소 가입 연령 미만)를 설명하고 복귀 경로를 제공한다 |

**랜딩 화면 카피 방향과 채널 조사 대조.** growth의 `channel-research.md`가 제시한 1순위 채널(네이버 블로그 오가닉 검색 SEO)은 "내가 절세 계좌를 제대로 쓰고 있는지 점검하려는 확인 욕구"를 동기로 본다. 이 문서가 애초에 가정했던 "검색 유입이 주력"이라는 전제 및 1절의 타깃 동기(어림짐작으로 납입해 오차가 큰 문제를 확인하고 싶은 사람)와 일치한다. 랜딩 화면 목적 문구를 조정할 필요가 없다고 판단해 위 open_questions에서 뺐다.

## 5. 결과 화면이 답해야 할 질문

- 지금 가진 월 납입 여력을 ISA·IRP·연금저축에 각각 얼마씩 넣어야 하는가?
- 그렇게 배분했을 때 올해 예상 절세 효과(세액공제 환급 추정치 등)는 얼마인가?
- 왜 이 배분인가 — 어떤 한도·조건 때문에 이렇게 나뉘었는가?
- 월 납입 여력이 세 계좌의 한도 합계보다 적어서 다 채우지 못한다면, 무엇을 우선 채워야 가장 이득인가?
- 반대로 여력이 한도 합계보다 많다면, 한도를 넘는 금액은 어떻게 되는가(추천 배분에서 제외된다는 사실)?
- 기존에 이미 납입한 금액은 이번 추천에 어떻게 반영되었는가?
- ISA 만기 자금을 연금계좌로 전환하면(전환 여부를 "예"로 입력한 경우) 추가로 늘어나는 세액공제 한도는 얼마이고, 그만큼 추천 배분이 어떻게 달라지는가?

## 6. 수용 기준(AC)

**입력 화면**

- 사용자가 나이·총급여액·월 납입 여력 중 하나라도 비워둔 채 "계산하기"를 누르면, 입력 화면은 계산을 진행하지 않고 비어 있는 항목에 오류를 표시한다.
- 사용자가 나이에 정수가 아닌 값(소수, 문자)을 입력하면, 입력 화면은 오류를 표시하고 해당 값을 계산에 사용하지 않는다.
- 사용자가 총급여액·월 납입 여력·기납입액 중 하나에 음수를 입력하면, 입력 화면은 오류를 표시한다.
- 사용자가 투자 성향을 선택하지 않고 다음으로 진행하면, 입력 화면은 "중립형"을 기본 선택값으로 미리 채워둔 상태를 유지한다(선택하지 않아도 진행 가능).
- 사용자가 연금저축·IRP·ISA 기납입액을 입력하지 않고 진행하면, 입력 화면은 해당 항목을 0으로 간주하고 진행을 막지 않는다.
- 사용자가 나이에 세무 유닛이 정의한 최소 가입 연령 미만 값을 입력하면, 입력 화면은 계산을 진행하지 않고 사유를 안내한다.
- 사용자가 ISA 누적 납입액을 0으로 입력하거나 비워두면, 입력 화면은 ISA 만기 전환 여부·전환 금액 항목을 표시하지 않는다.
- 사용자가 ISA 만기 전환 여부를 "예"로 선택하고 전환 금액을 비워두거나 ISA 누적 납입액을 초과하는 값을 입력하면, 입력 화면은 계산을 진행하지 않고 해당 항목에 오류를 표시한다.
- 사용자가 ISA 만기 전환 여부를 "아니오"로 두거나 선택하지 않으면, 입력 화면은 전환 금액·직전 과세기간 적용액을 0으로 간주하고 진행을 막지 않는다.
- 모든 필수 항목이 유효한 값으로 채워지면, "계산하기" 버튼이 활성화된다.

**결과 화면**

- 사용자가 유효한 입력으로 계산을 요청하면, 결과 화면은 ISA·IRP·연금저축 세 계좌 각각에 대한 추천 납입액을 숫자로 표시한다.
- 월 납입 여력이 세 계좌의 잔여 한도 합계보다 적으면, 결과 화면은 한도를 다 채우지 못했다는 사실과 우선순위(어느 계좌부터 채웠는지)를 함께 표시한다.
- 월 납입 여력이 세 계좌의 잔여 한도 합계 이상이면, 결과 화면은 세 계좌 모두 잔여 한도까지 채우는 배분을 제시하고 남는 금액이 있다는 사실을 표시한다.
- 사용자가 기존 납입액(연금저축·IRP·ISA)을 입력했으면, 추천 배분은 각 계좌의 한도에서 기존 납입액을 제외한 잔여 한도 내에서만 계산되어 표시된다.
- 사용자가 ISA 만기 전환 여부를 "예"로 입력하고 계산을 요청하면, 결과 화면은 전환으로 늘어난 연금계좌 세액공제 추가 한도를 별도 항목으로 표시하고, 그 한도가 연금저축·IRP 추천 배분에 반영되었음을 보여준다.
- 사용자가 ISA 만기 전환 여부를 "아니오"로 입력하거나 표시하지 않았으면, 결과 화면은 전환 관련 추가 한도 항목을 표시하지 않는다.
- 결과 화면은 "세법 계산 예시이며 투자·세무 자문이 아님" 고지 문구를 예외 없이 표시한다.
- 결과 화면은 특정 금융상품명·금융사명을 표시하지 않는다.
- 결과 화면은 사용자가 입력한 나이·소득·기존 납입액 등 개인 값을 서버로 전송하지 않고 브라우저 내 계산 결과만 표시한다.
- 사용자가 "저장·공유"를 실행하면, 생성되는 결과물(이미지·링크 등)에는 나이·소득 등 개인 식별 가능 입력값이 포함되지 않는다.

**오류·안내**

- 계산이 불가능한 입력 상태(예: 최소 가입 연령 미만)에서는, 결과 화면으로 진행하지 않고 사유와 복귀 경로(입력 화면으로 돌아가기)를 함께 보여준다.

**비범위 검증**

- 어떤 화면에서도 로그인·회원가입을 요구하지 않는다.
- 어떤 화면에서도 광고나 유료 결제 유도 요소를 표시하지 않는다.

## 7. 비범위

- 종합소득자(자영업자·프리랜서 등) 전용 소득 입력 처리 — 1차 출시는 근로소득자(총급여 기준)만 다룬다(게이트 1 D2 확정, `docs/org/gate-decisions.md`).
- 부양가족 공제 등 연말정산의 다른 항목과의 통합 계산.
- 특정 금융상품·금융사 추천 또는 상품 비교·가입 연결.
- 로그인, 회원가입, 사용자 계정, 서버에 개인 입력값 저장.
- 여러 번의 계산 이력을 서버에 저장해 추적하는 기능.
- 모바일 네이티브 앱(반응형 웹만 다룬다).
- 유료 기능, 광고, 제휴 상품 노출 — 출시 버전은 수익화·광고가 없다(헌장 제품 원칙 7).
- 다년도·은퇴 시점까지의 복리 시뮬레이션 — 이번 버전은 당해 연도 최적 배분에 한정한다.
- ISA 만기 전환의 손익분기점·수수료 비교 시뮬레이션 — 전환 시 늘어나는 세액공제 한도 자체는 이번 범위에 포함됐지만(2절·게이트 1 D3), "전환하는 것이 유리한지"를 손익분기점·수수료로 따져주는 별도 시뮬레이션은 이번 범위에 포함하지 않는다.
- **연금 인출 단계 시뮬레이션(v2로 연기, 게이트 1 D3 확정)** — 연금수령한도 계산, 이연퇴직소득 감면율 적용 등 인출 단계에 필요한 계산은 이번 버전에서 다루지 않는다. 근거: 인출 계산에 필요한 두 수치 — 연금수령한도 산식(소득세법 시행령 §40조의2 ③3)과 이연퇴직소득 감면율(수령연차 구간) — 를 tax-domain이 1차 출처(조문 원문)로 확인하지 못했다(`tax-rules-report.md` 4절·5절 쟁점1). 출처 없는 규칙은 무효라는 제품 원칙 2에 따라, 이 두 수치가 출처와 함께 확정되기 전에는 인출 화면을 만들 수 없다.
- 세무사·재무설계사 상담 연결.

## 8. 경쟁·유사 서비스 조사

| 서비스 | 무엇을 해주는가 | 무엇을 안 해주는가 |
|---|---|---|
| 쿼터백연금연구소 — 연금저축·IRP 세액공제 계산기 (qbr.co.kr/retirement-calc/tax-deduction) | 사용자가 직접 입력한 연금저축·IRP 납입액과 총급여를 받아 세액공제 환급액을 계산해 보여준다 | 사용자가 "얼마를 넣어야 하는지"는 정해주지 않는다. 입력값은 사용자가 이미 결정한 금액이라는 전제이고, ISA는 계산 범위에 없다 |
| 쿼터백연금연구소 — ISA→IRP 전환 계산기 (qbr.co.kr/retirement-calc/isa-irp) | ISA 만기 자금을 IRP·연금저축으로 전환할 때의 추가 세액공제와 손익분기점을 계산한다 | 세 계좌를 동시에 놓고 월 납입 여력을 배분하는 문제는 다루지 않는다. ISA 만기라는 단일 이벤트에 한정된 전환 시뮬레이션이며, 나이·투자 성향별 맞춤 배분은 제시하지 않는다 |
| 토스뱅크 — 연금저축·IRP 세액공제 안내 페이지 (tossbank.com/articles/pension-savings-tax-deduction) | 세액공제율·한도를 표와 고정 예시("총급여 5,200만원이면 148.5만원")로 설명하는 교육 콘텐츠를 제공한다 | 사용자가 자기 값을 입력해 결과를 받는 인터랙티브 기능이 없다. 모든 사람에게 같은 예시만 보여준다 |
| 뱅크샐러드 — 연금저축·IRP 세액공제 총정리 (banksalad.com) | 소득 구간별 세액공제율·환급액 표를 정리해 보여주는 정보성 글을 제공한다 | 계산기가 없다. 글 끝에서 "30개사 상품 비교"로 사용자를 유도해, 계좌 배분 문제를 상품 비교·가입 퍼널로 대체한다 |

**이 서비스가 다르게 하는 것 (한 문장).** 위 서비스들은 하나같이 사용자가 "얼마를 넣을지"를 이미 정했다는 전제에서 세액공제액을 계산해주거나(쿼터백 세액공제 계산기), 단일 이벤트(ISA 만기 전환)만 다루거나(쿼터백 전환 계산기), 계산 자체를 제공하지 않고 정보나 상품 비교로 안내한다(토스뱅크, 뱅크샐러드) — 이 서비스는 반대로 "월 납입 여력"이라는 하나의 예산만 입력받아, 나이·소득·투자 성향·기존 납입 현황을 함께 고려해 ISA·IRP·연금저축 세 계좌에 얼마씩 나눠 넣을지 그 배분 자체를 산출해준다.
